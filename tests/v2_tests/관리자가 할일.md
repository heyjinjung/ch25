    ###3.검증 자동화/Fail Fast 전략

    정기적 SoT-실체 동기화 점검
    주기적으로(예: 매일/배포 전) SoT-코드-DB-운영 상태를 자동 비교하여 drift 발생 시점/원인 추적 

    3-1. 오류 캡처/재현 자동화
    3-2. 반복 오류 자동 감지/캡처
        실행 위치: 테스트(CI), 운영 로그, QA 자동화, 배포 훅 등
        방법:
        pytest, unittest, shell script, custom python script 등에서
        동일 오류(에러 메시지, 스택트레이스, DB deadlock, API 500 등) 반복 감지 시
        해당 시점의 입력값, 환경, 로그, DB 상태, API 요청/응답 등 자동 저장
    3-3. 재현 스크립트 자동 생성
        형식:
        Python: debug_XXX.py, reproduce_XXX.py
        Shell: reproduce_XXX.sh
        SQL: reproduce_XXX.sql
        기타: markdown(재현 절차), json(입력값), csv(테스트 데이터) 등
        내용:
        오류 재현에 필요한 최소 입력/환경/명령/쿼리/시나리오
        예: scripts/debug_streak_claim_deadlock.py, scripts/reproduce_admin_import_error.sh
    3-4. 스크립트 저장 위치
        경로:
        docs/scripts/ (없으면 새로 생성)
영역별로 하위폴더 분리 권장 (예: docs/scripts/mission/, docs/scripts/vault/, docs/scripts/admin/ 등)
파일명 규칙:
debug_{영역}{오류명}{날짜}.py

{영역}/{이슈명}_{날짜}.md
