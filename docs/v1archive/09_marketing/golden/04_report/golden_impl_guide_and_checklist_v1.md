## 1) Dynamic Quest Engine (가변 미션/개인화 퀘스트)

## 1-1) 데이터 소스 확보/정의
- [ ] 상태 입력 필드 확정(loss_streak/inactivity_days/psych_state/segment_tag)
- [ ] 권장 확장 필드 확정(last_login_at/today_play_count/avg_bet_amount)
- [ ] 입력 필드 최신성 기준(갱신 주기/TTL) 확정

## 1-2) 원본 → 미션 조건 변환 규칙
- [ ] 트리거 룰 고정
  - [ ] loss_streak > 3 → 회복 미션
  - [ ] inactivity_days > 3 → 복귀 미션
  - [ ] psych_state = FRUSTRATED → 위로형 미션
  - [ ] today_play_count = 0 → 데일리 진입 유도
- [ ] 미션 구성 요소 정의(condition/reward/ttl/cap)
- [ ] 중복 방지 키 설계(유저/일/미션 타입)

## 1-3) 생성/갱신 파이프라인
- [ ] `user_daily_mission` 스키마 정의
- [ ] 생성 시점 정의(실시간/배치)
- [ ] 만료/갱신 정책 정의(당일/48시간)

## 1-4) 실행/지급 처리
- [ ] 완료 조건 판정 로직 확정
- [ ] 지급 성공/실패/만료 상태 정의
- [ ] 보상 지급 경로(티켓/토큰/미션 포인트) 확정

## 1-5) 실시간 전달/노출
- [ ] 미션 노출 UI 위치 확정
- [ ] 미션 갱신 시 UI 반영(재조회/WS) 방식 확정

## 1-6) 운영 증거 수집 (필수)
- [ ] 미션 생성/갱신 DB row 캡처
- [ ] 미션 완료/지급 로그 캡처
- [ ] UI 노출 스크린샷 확보
  - [ ] 담당자(백엔드/프론트/운영) 지정
  - [ ] 증거 링크 템플릿 작성(아래)

## 3) Predictive Re-engagement (예측 재참여)

## 3-1) 데이터 소스 확보/정의
- [ ] 최소 입력 필드 확정(churn_probability_score/recency/loss_streak)
- [ ] 권장 필드 확정(predicted_ltv/last_intervention_at/segment_tag)
- [ ] 점수 갱신 주기 확정(일 배치/실시간)

## 3-2) 트리거/규칙 변환
