# 2026-01-15 개발 로그: 미션 시스템 및 상점 로직 개선

## TL;DR
- 미션 액션 타입 미스매치(`PLAY` vs `PLAY_GAME`)를 해결하여 게임 플레이 미션 카운트가 정상 작동하도록 수정했다.
- 어드민 상점에서 VAULT 상품 저장 시 발생하는 Enum 직렬화 오류를 수정했다.
- 금고(VAULT)로 티켓 구매 시 인벤토리 바우처를 거치지 않고 직접 티켓이 지급되도록 개선했다.

## 변경사항

### 1) 미션 시스템: 액션 타입 호환성 및 어드민 설정 개선
- **문제**: 어드민에서 `"PLAY"`로 생성한 미션이 백엔드의 `"PLAY_GAME"` 트리거와 매칭되지 않아 카운트 누락 발생.
- **해결**: 
  - 백엔드 `MissionService`에서 `"PLAY"`와 `"PLAY_GAME"`을 상호 호환되도록 쿼리 로직 보강.
  - 스트릭(Streak) 동기화 조건에도 `"PLAY"`를 추가하여 기존 미션들의 연속성 보장.
  - 어드민 미션 관리 페이지의 액션 타입 목록을 `"PLAY_GAME"`으로 수정하고, 로그인/초대 등 주요 타입 추가.
- **관련 파일**: `app/services/mission_service.py`, `src/admin/pages/AdminMissionPage.tsx`

### 2) 어드민 상점: VAULT 상품 저장 오류 수정
- **문제**: 상점 상품 저장 시 `VAULT` 토큰 타입 Enum이 JSON으로 직렬화되지 않아 에러 발생.
- **해결**: Pydantic `model_dump` 호출 시 `mode='json'` 옵션을 추가하여 해결.
- **관련 파일**: `app/api/admin/routes/admin_shop.py`

### 3) 상점 서비스: 금고 결제 시 티켓 직결 지급
- **문제**: 금고로 티켓 구매 시 인벤토리에 "교환권"으로 들어가 한 번 더 사용해야 하는 번거로움과 작동 불능 이슈.
- **해결**: 결제 수단이 `VAULT`이고 보상이 티켓류인 경우, `GameWalletService`를 통해 즉시 티켓 수량을 증가시키도록 로직 변경.
- **관련 파일**: `app/services/shop_service.py`

## 확인 필요 (QA)
- 어드민에서 새로 만든 "플레이 (Game Play)" 미션의 카운트가 실제 게임 플레이 시 올라가는지 확인.
- 금고 잔액으로 티켓 상품 구매 시 인벤토리를 거치지 않고 사용 가능 티켓 잔액이 즉시 증가하는지 확인.
- 어드민 상점에서 VAULT 결제 상품이 에러 없이 저장되는지 확인.
