# 도파민06 백엔드 구현 계획서 (Roadmap & Social/Security)

작성일: 2026-01-14  
범위: 도파민06_로드맵_및_기타_가이드 기준 (Social Proof + Smart Friction + Cherry Picker 대응)

---

## 1) 목표 및 범위

- **Social Proof**: 실시간 피드(당첨/환전/레벨업) 제공
- **Smart Friction**: 출금 시점만 보안 심사/롤링 적용
- **Cherry Picker 방어**: Risk Score/Shadow Ban 기반 격리
- **Admin 도구**: 피드 컨트롤러/Shadow Ban 관리자 기능

---

## 2) 단계별 구현 로드맵

### 2.1 데이터 모델 확장

- `users`
  - `risk_score` (Float, default 0)
  - `shadow_banned` (Boolean, default false)
- (선택) `feed_event` 테이블
  - 실시간 피드 이벤트 저장 및 캐싱 용도

### 2.2 Social Proof 서비스

- `FeedService`
  - **실제 로그 + 봇 로그 혼합(7:3)** 로 피드 구성
  - 데이터 소스: `GameLog`, `WithdrawalRequest`, `SeasonPassRewardLog`
  - 닉네임 마스킹 규칙 적용 (예: `ji***`)
- API
  - `GET /api/feed/live` (최근 N건)
  - `GET /admin/api/feed/templates` (피드 템플릿 관리)

### 2.3 Smart Friction (보안 심사)

- 출금 요청 시 조건 검사
  - `total_bet / total_deposit < 3.0` → `ManualReview`
  - `shadow_banned == true` → `PendingReview` 고정
- 로직 적용 위치
  - `VaultService.request_withdrawal` 또는 `WithdrawalService`

### 2.4 Admin 도구

- Feed Controller
  - 봇 로그 활성/비활성
  - 템플릿/비율 조정
- Shadow Ban Manager
  - `risk_score`, `shadow_banned` 수정
  - 유저 목록 필터 및 상태 변경 로그

### 2.5 관측/로그

- 피드 노출/클릭 로그 (optional)
- 출금 상태 변경 로그 (ManualReview/PendingReview)

### 2.6 테스트/검증

- FeedService
  - 마스킹 규칙 및 혼합 비율 테스트
- Smart Friction
  - 조건 미달 시 ManualReview 전환 검증
  - Shadow Ban 강제 대기 검증

---

## 3) 릴리즈 전략

- 피드 기능은 **봇 비율 100% → 70/30 → 50/50** 순으로 축소
- Smart Friction은 VIP/일반 세그먼트별 단계적 적용
