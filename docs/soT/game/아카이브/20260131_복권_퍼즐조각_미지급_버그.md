## 3. 근본 원인 분석 (Root Cause)

### 🔴 주요 원인 1: DB 설정 오류
`v2_lottery_prize` 테이블에서 **PUZZLE_C2의 `reward_amount`가 0으로 설정**됨.
- PUZZLE_C1: `reward_amount=1` ✅
- PUZZLE_C2: `reward_amount=0` ❌

### 🟠 부차 원인 2: PUZZLE_C/C1/C2 혼용
- `GameTokenType` enum에 `PUZZLE_C`, `PUZZLE_C1`, `PUZZLE_C2` 모두 존재
- `user_game_wallet`에는 `PUZZLE_C`로 저장된 레거시 데이터
- 복권 상품은 `PUZZLE_C1`, `PUZZLE_C2`로 분리 설정
- `get_status()`에서 `PUZZLE_C` 기준으로 C1/C2 계산 (불일치)

### 흐름도
```
복권 플레이 → 당첨: PUZZLE_C2 (prize_id=7)
           ↓
v2_lottery_prize 조회 → reward_amount=0
           ↓
reward_service.deliver(amount=0) → Early Return (아무것도 안함!)
           ↓
user_game_wallet에 토큰 미지급
```

## 4. 해결책 (Solution)

### 4.1 DB 마이그레이션 (생성 완료)
**파일**: `alembic/versions/20260131_0500_puzzle_c_deprecation_cleanup.py`

1. **v2_lottery_prize 수정**: PUZZLE_C2 `reward_amount` 0→1
2. **user_game_wallet 마이그레이션**: PUZZLE_C 잔액 → PUZZLE_C1로 이전
3. **감사 로그**: user_game_wallet_ledger에 마이그레이션 기록

### 4.2 백엔드 코드 수정 (완료)

| 파일 | 변경 내용 |

| | `play()`: puzzle drop에서 C1/C2/J/M 4개 중 랜덤 |
| `app/services/lottery_service.py` | V1 호환: PUZZLE_C → C1/C2 개별 조회 |
| `app/models/game_wallet.py` | `PUZZLE_C` DEPRECATED 주석 추가 |

### 4.3 프론트엔드 수정 (완료)
