## 3. 정합성 검증 요약 리포트 (Step 1)

- **상태**: 🟡 **업데이트 필요 (Step 3-3: Codebase Verification)**
- **주요 발견 사항**:
    - 🟢 [정책/구현 일치]: **자산 3단계 분류**. Token(대체가능)과 Item(비대체/스택)이 DB 테이블(`UserGameWallet` vs `UserInventoryItem`) 레벨에서 명확히 분리되어 있음.
    - 🟢 [서비스 구조]: `InventoryService`(조회/사용)와 `ShopService`(구매)가 분리되어 설계 원칙을 준수함.
    - 🔴 [운영 구현 누락]: **강력한 금고 정책**. `ShopService.purchase` 및 `InventoryService.use_voucher` 로직 내에 `benefits_suspended=True` 유저를 차단하는 코드가 전혀 없음. 즉시 구매/사용 가능하여 정책 위반 상태임.
    - 🔴 [운영 리스크]: **상점 UI 설정(`v2_shop_products`)**. 해당 설정값이 누락되거나 비어있으면 상점 목록이 아예 노출되지 않는 구조임(Empty Array). 운영 시 필수 체크 항목.
    - 🟡 [검토 필요]: **기프티콘 네이밍**. 표준 포맷(`{BRAND}_GIFTICON_{AMOUNT}`)이 문서에는 명시되어 있으나, 실제 DB에 적재된 데이터가 이를 100% 준수하는지(오타, 소문자 등)는 별도 DB 쿼리 검증이 필요함.
    - 🟡 [의존성]: `app.models.inventory`는 V1 공용 모델을 사용 중임. V2 전용 모델로의 이관 필요. (`app/v2/services/inventory_service.py` -> `app.models.inventory` 참조 확인)
    - 🟡 [프론트엔드]: `inventory`, `shop` 페이지가 현재 Redesign 상태(🚧).

## 4. 코드베이스 실전영역 체크 리포트 (Step 3-3)

- **검증 일시**: 2026-01-26
- **검증 대상**: `app/v2/services/shop_service.py`, `app/v2/services/inventory_service.py`, `app/models/inventory.py`
- **주요 발견 사항**:
    - 🔴 **[정책 누락] Strict Vault Policy**: `ShopService.purchase` 메서드 진입부에 유저의 `benefits_suspended` 상태를 체크하는 로직이 부재함. 무입금/장기 미접속 유저도 상점 이용이 가능한 상태.
    - 🟢 **[로직 정합] Exchange Log**: `V2InventoryService.log_exchange`는 단순히 로그만 남기는 메서드로, 분해(Breakdown) 로직이 포함되지 않아 "비가역성" 정책을 준수함.
    - 🟡 **[모델 혼용] V1 Model Dependency**: `V2InventoryService`가 `app.models.inventory.UserInventoryItem`을 직접 import하여 사용 중. 기능상 문제는 없으나, 장기적으로 `app.v2.models`로의 분리(Namespace Isolation)가 권장됨.
    - 🟢 **[트랜잭션] Shop Purchase**: `purchase` 메서드 내에서 잔액 차감(`user.vault_locked_balance`)과 로그 생성(`V2ShopOrder`), 보상 지급(`grant_reward`)이 하나의 DB 세션 내에서 수행되진 않으나(grant_reward는 내부적으로 별도 로직), `purchase` 자체는 flush를 수행함. (엄밀한 Atomic 보장을 위해서는 `grant_reward`의 트랜잭션 전파 확인 필요)

- **종합 의견**: 인벤토리 및 상점의 기본 기능(구매/사용/저장)은 정상 구현되어 있으나, **V2 핵심 운영 정책인 "강력한 금고 정책(이용 차단)"이 실제 코드에 반영되지 않았음.** 이는 정책과 구현의 치명적 불일치로, 오픈 전 반드시 `ShopService` 등에 가드 로직을 추가해야 함.

## 4. 알기 쉬운 불일치 설명 (For Beginners)

### 🟡 1. 기프티콘 이름 규칙 (이름표를 똑바로 붙였나요?)
- **무슨 규칙인가요?**: 편의점에서 물건 정리할 때 "브랜드_상품_가격" 순서로 이름표를 붙이기로 했어요. (예: 스타벅스_기프티콘_5000)
- **왜 확인해야나요?**: 만약 누군가 실수로 "스타벅스 5000"이라고만 쓰거나 "스벅_5000"이라고 줄여 쓰면, 계산기(시스템)가 못 알아볼 수 있어요. 아직 확인을 못 해봐서 "검토 필요"라고 표시했어요.

### 🟡 2. 공용 창고 사용 (이사 갈 준비 중)
- **무슨 상황인가요?**: V2(새 집)로 이사를 왔는데, 옷장(인벤토리 DB)은 아직 V1(옛날 집)이랑 같이 쓰고 있어요.
- **문제 있나요?**: 당장은 괜찮지만, V1 집을 완전히 철거할 때 옷장도 같이 부서질 수 있어서 조심해야 해요. 나중에 V2 전용 옷장으로 짐을 옮기는 작업이 필요해요.

### 🟡 3. 강력한 금고 정책 (돈 안 내면 이용 제한)
- **무슨 정책인가요?**: 7일 동안 입금을 안 하면(무입금), 상점이나 유료 게임을 못 하게 막는 규칙이에요.
- **왜 확인해야나요?**: 문서에는 "막아야 한다"고 되어 있는데, 실제로 문지기(서비스 코드)가 잘 막고 있는지 아직 확인을 안 해봤어요. 몰래 들어가는 사람이 없는지 검사가 필요해요.

### 🔴 4. 상점 진열대 설정 (빈 진열대 조심!)
- **무슨 문제인가요?**: 상점에 물건(상품)을 진열하려면 `v2_shop_products`라는 설정 파일에 상품 목록을 적어야 해요.
- **왜 위험한가요?**: 만약 운영자가 실수로 이 파일을 비워두거나 지워버리면, 손님이 상점에 들어왔을 때 **아무것도 없는 빈 화면**을 보게 돼요. "오픈 준비 중" 팻말이라도 있으면 다행인데, 그냥 텅 비어있으면 오류 난 줄 알겠죠? 운영할 때 꼭 챙겨야 하는 부분이에요.
