## 1. 목적 (Purpose)
레벨포인트(XP)의 **획득 원천/계산 규칙/제한 정책**을 최종 확정한다.

## 2. 범위 (Scope)
- CC 입금 기반 XP 적립 규칙
- 일일 제한 정책(폐기) 및 운영 해석
- 향후 확장(게임별 XP) 상태 정의

## 3. 핵심 결론
- CC 입금 기반 XP 적립은 다음이 최종 SoT이다.
  - 100,000원 당 XP 20 적립
  - **일일 적립 한도 없음** (2026-01-28 폐기)
- 게임 플레이 기반 XP(룰렛/주사위/복권)는 현재 문서 기준 **제안 수령(미구현)** 상태로 유지한다.

## 3.1 비목표(Non-Goals)
- 본 문서는 “레벨 보상 지급” 자체의 규칙을 정의하지 않는다.
- 본 문서는 Vault 재화의 적립/차감/락 규칙을 정의하지 않는다.

## 4. CC 입금 XP 규칙 (Primary)
### 4.1 계산
- Step 금액: 100,000원
- Step 당 XP: 20

즉, 입금액이 $A$원일 때 적립 XP는 다음으로 계산한다.

$$\mathrm{xp} = \left\lfloor \frac{A}{100{,}000} \right\rfloor \times 20$$

#### 4.1.1 입력값 정규화
- 금액 문자열(콤마/공백/원/₩ 등)이 입력되더라도 최종적으로 **정수 원 단위**로 파싱한다.
- $A \le 0$ 또는 파싱 불가능 케이스는 XP 적립 대상이 아니다.

#### 4.1.2 라운딩/잔여 금액
- $A$원에서 100,000원 미만의 잔여 금액은 XP로 환산하지 않는다.
- 예) 199,999원 → 20XP, 200,000원 → 40XP

### 4.2 일일 한도 정책
- 과거 운영상 “일일 최대 XP” 제한(1000→300→100)이 존재했으나, 2026-01-28에 **완전 폐기**되었다.
- 따라서 동일 일자에 여러 번 입금하더라도 clamp(상한 제한)는 적용하지 않는다.

### 4.3 `source`(원천) 값 표준
`user_xp_event_log.source`는 운영/분석에서 **사유 식별이 가능**해야 하므로, 아래 원칙을 따른다.

- CC 입금 기반 적립: `CC_DEPOSIT`
- 어드민 수동 조정: `ADMIN_ADJUST` 또는 `ADMIN_SET` (조직 표준으로 1개로 고정 권장)
- 미션/이벤트 기반 적립: `MISSION_CLEAR` 등
- 게임 기반 적립(향후): `GAME_PLAY` 등

권장:
- source 문자열은 **대문자 스네이크**(예: `CC_DEPOSIT`)로 고정한다.
- `meta`(또는 동등 필드)에 적립 근거(입금 배치 id, 임포트 라인, 어드민 티켓 번호 등)를 남긴다.

### 4.4 예시 (Examples)
- 50,000원 → 0XP
- 100,000원 → 20XP
- 350,000원 → 60XP
- 같은 날 100,000원 + 100,000원 → 40XP (일일 한도 없음)

## 5. 기타 획득 원천(확장)
### 5.1 게임별 레벨포인트
- 룰렛/주사위/복권 레벨포인트: **제안 수령(미구현)**
- 구현 착수 시 필수 명시 사항:
  - 적립 조건(베팅/승패/금액)과 상수(환산 비율)
  - 악용 방지(봇/반복) 정책
  - XP 이벤트 로그의 `source` 값 표준

### 5.2 미션/이벤트
- 응답 스키마에서 `xp_reward` 같은 필드가 존재하더라도, “실제 XP 적립”은 반드시 본 문서의 규칙과 `user_xp_event_log` 감사 규칙을 만족해야 한다.
