## 1. 목적
- 금고 운영 규칙과 트러블슈팅 기준을 통합한다.
- 증거 기반 RCA와 풀스택 검증 원칙을 고정한다.
- 운영 일관성과 배포 안정성을 확보한다.

## 2. 범위
- 운영 체크리스트
- 트러블슈팅 프로토콜
- 배포 전후 검증
- 로그/스냅샷 기록 규칙

## 3. 운영 기본 원칙
- SoT 기준: user.vault_locked_balance 단일 기준
- KST 09:00 리셋 정책 준수
- VaultLedger 기록 누락 금지
- 혜택 중단은 서비스 레이어에서 강제 차단

## 4. 증상 정의 포맷
| 항목 | 내용 |
| --- | --- |
| 대상 기능 | 예: 출금 승인, 상점 구매 |
| HTTP Status | 500/400/200 |
| 영향 범위 | 특정 유저/전체 |
| 재현 빈도 | 항상/간헐 |

## 5. 증거 기반 RCA
- 로그와 DB 제약조건을 증거로 제시한다.
- 추측 금지.
- VaultLedger, vault_withdrawal_request, v2_spending_ledger 확인.
- 원장 기록 누락이 가장 우선적인 의심 포인트다.

## 6. 풀스택 검증
- DB: 마이그레이션 체인, 제약조건, 스냅샷 확인
- API: 응답 필드 정규화 확인
- FE: 출금 조건 모달 표시 확인
- Admin: 원장 조회 및 강제 조정 로그 확인

## 7. 운영 체크리스트
- benefits_suspended 차단 403 동작 확인
- 상점 구매 후 daily_vault_spent 증가 확인
- 출금 조건 플레이 카운트 계산 확인
- VaultLedger 최신 10건 확인
- Admin 집계가 locked 단일 기준인지 확인

## 8. 긴급 이슈 대응
- VaultLedger 우회 경로 발견 시 즉시 차단
- 보상 적립 경로는 deposit로 통일
- Admin 수동 조정은 reason 필수
- 롤백이 필요한 경우 금고 원장과 지출 원장을 함께 확인

## 9. 배포 전 체크
- alembic current 확인
- 주요 테스트 통과 확인
- 샘플 유저 금고 잔액 비교
- 사용 금액 리셋 기준이 09:00 KST인지 확인

## 10. 배포 후 체크
- VaultLedger 레코드 증가 확인
- Admin 금고 내역 조회 정상 확인
- 출금 승인/반려 로그 확인
- 상점 구매 후 잔액 및 사용 금액 반영 확인

## 11. 리포트 및 증거 저장
- 스냅샷과 로그는 docs/SOT/vault/db_snapshots.md에 기록
- 테스트 결과는 test_results_YYYYMMDD.md로 기록
- 재현 로그는 사건별로 증거 링크를 남긴다.

## 12. 알려진 위험
- 레거시 available 잔존 데이터
- Admin 집계 합산 드리프트
- API 응답 필드 혼재
- 레거시 경로 혼재로 인한 정책 표현 불일치

## 13. 대표 트러블슈팅 시나리오
### 13.1 출금 조건 모달 값이 0으로 표시
- 원인: snake/camel 혼재, 정규화 누락
- 확인: vault/status 응답 필드 확인
- 조치: 응답 정규화 및 fallback 적용

### 13.2 상점 구매 후 오늘 사용 금액 미증가
- 원인: 소비 전용 메서드 미사용
- 확인: vault_spent_today 증가 여부 확인
- 조치: consume_locked_for_spend 경로 적용

### 13.3 주사위 패배 시 금고 차감 미발생
- 원인: limit 체크 조기 종료
- 확인: amount 음수 처리 여부 확인
- 조치: 양수 적립만 제한되도록 수정

### 13.4 Admin 강제 조정 로그 누락
- 원인: VaultLedger 기록 누락 경로
- 확인: vault_ledger 레코드 확인
- 조치: ref_type=ADMIN 기록 추가
