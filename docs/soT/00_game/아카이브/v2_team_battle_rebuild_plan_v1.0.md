# V2 팀배틀 재정비 계획서 (SoT 수립부터 백엔드 구현까지)

## 1. 목적 (Purpose)
보상단위 변경에 따라 팀배틀 영역을 SoT 수립부터 백엔드 구현까지 일괄 재검증하고, v2 표준과 일치하는 최종 구현을 완료한다.

## 2. 범위 (Scope)
- 팀배틀 SoT 수립 및 갱신(정책/보상단위/데이터 모델/API 스키마)
- 백엔드 현황 파악(모델, 서비스, 라우트, 스키마, 설정값)
- 수정 대상 영역 리스트업 및 우선순위 확정
- 백엔드 구현/테스트/문서 갱신

## 3. 용어 정의 (Definitions)
- SoT(Source of Truth): 변경/판단 기준이 되는 단일 기준 문서
- 보상단위: 보상 값이 적재/지급되는 기준 단위(예: manual_coupon, vault_locked_balance 등)
- 팀배틀: 시즌/팀/멤버십/점수/보상 정산 흐름으로 구성되는 게임 모드

## 4. 전제 및 입력 아티팩트
- 기존 SoT: docs/v2_specs/02_game/v2_team_battle_sot_ko.md
- 보상 표준: docs/v2_specs/01_core/v2_reward_type_standard_sot_ko.md
- 보상 매핑: docs/v2_specs/01_core/v2_reward_mapping_sot_ko.md
- 백엔드 코드: app/models/team_battle.py, app/services/team_battle_service.py, app/api/routes/team_battle.py, app/schemas/team_battle.py, app/core/config.py
- 운영/정책 변경 내역(보상단위 변경 근거 문서)

## 5. 작업 범위 단계별 계획

### 5.1 1) SoT 수립
1) 목표
- 팀배틀 SoT에 보상단위 변경 내용을 반영하고, 정책/데이터/스키마 기준을 확정한다.

2) 수행 항목
- 보상단위 변경 근거 문서 확인 및 정책 문구 확정
- 팀배틀 SoT 문서의 보상 정산 섹션 재정의
- RewardType 표준/보상 매핑 SoT와의 정합성 확인

3) 산출물
- 팀배틀 SoT 갱신안(보상단위/정산 흐름/예외 규칙 포함)

4) 완료 기준
- SoT 문서에서 보상단위가 단일 기준으로 확정되고 상충 규칙이 제거됨

### 5.2 2) 백엔드 현재 현황 파악
1) 목표
- 현재 구현이 어떤 보상단위를 사용하고 있으며 어떤 데이터 흐름으로 처리되는지 확인한다.

2) 수행 항목
- 모델: team_season.rewards_schema 구조 및 실제 DB 데이터 확인
- 서비스: 포인트 계산/정산/보상 반환 로직의 단위 확인
- API: 응답 스키마에서 보상 필드 단위 확인
- 설정값: config 상수 및 운영 파라미터 확인

3) 산출물
- 현황 요약 표(파일/함수/필드/보상단위/비고)

4) 완료 기준
- 보상단위가 반영되는 모든 위치가 목록화됨

### 5.3 3) 수정할 영역 리스트업
1) 목표
- SoT와 불일치하거나 보상단위 변경에 영향받는 영역을 선별한다.

2) 수행 항목
- SoT 대비 불일치 항목 분류(정책/DB/서비스/API)
- 변경 난이도/리스크 기준으로 우선순위 부여
- 마이그레이션/데이터 정합성 이슈 여부 판단

3) 산출물
- 수정 대상 리스트(파일/영향/우선순위/검증 포인트)

4) 완료 기준
- 수정 대상이 실행 가능한 범위로 확정됨

### 5.4 4) 백엔드 구현
1) 목표
- SoT 기준을 반영하여 팀배틀 보상단위 및 흐름을 구현한다.

2) 수행 항목
- 서비스 로직 수정 및 필요한 스키마/모델 보완
- 필요 시 Alembic 마이그레이션 추가
- 테스트 및 검증 로그 확보
- 문서 갱신 및 변경 이력 반영

3) 산출물
- 코드 변경(PR)
- 테스트 결과 로그
- 문서 갱신(SoT/체크리스트/변경 로그)

4) 완료 기준
- SoT/구현/테스트가 일관되며 운영 기준에 부합함

## 6. 운영/어드민 이슈 반영 항목
1) KST 전환 이후 시즌 생성/인식 실패

- 시즌 조회/활성화 로직이 생성 직후에도 인식 가능한지 확인

2) 어드민 프론트에서 시즌 삭제 불가
- 삭제 API 호출 실패 여부(권한/응답코드) 확인
- 삭제 시 연관 데이터 삭제 순서/제약 조건 점검

3) 초기 배치 랜덤 로직 미실행
- 배치 트리거 조건/스케줄러 동작 여부 점검
- 배치 실행 로그 및 실행 결과 저장 방식 확인

4) 운영 어드민 중심 오류 재현/로그 확보
- 운영 플로우 기준 재현 시나리오 작성
- 실패 시점의 요청/응답/DB row 스냅샷 확보
