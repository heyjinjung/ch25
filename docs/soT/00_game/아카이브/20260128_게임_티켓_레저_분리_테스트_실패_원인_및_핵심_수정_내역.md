## 1. 증상 요약
- 대상 기능: 게임(룰렛/주사위/로또) 티켓 사용 시 레저 분리 기록
- 테스트: tests/v2_tests/phase3_game/test_game_ledger_separation.py
- 실패 케이스:
  - test_roulette_ledger_separation
  - test_dice_ledger_separation
  - test_lottery_ledger_separation
  - test_roulette_ticket_fallback_consumes_legacy_once
- 증상: 게임 플레이 시 UserGameWalletLedger에 티켓 차감(-1) 레코드가 1건만 기록되어야 하나, 실제로는 기록이 누락되거나, 잘못된 토큰 타입으로 기록됨

## 2. 원인 분석 (Evidence-Based RCA)
- DB/코드 증거:
  - GameWalletService.require_and_consume_token()에서 티켓 차감 시 _log_ledger()로 UserGameWalletLedger에 기록
  - roulette_service.py 등 각 게임 서비스에서 play() 호출 시 require_and_consume_token()을 통해 티켓 차감
  - GameTokenType Enum 및 grant_tokens() 등에서 V2 표준(RO신규 유저 미션 카운트 오류의 재현 시나리오(미션 카테고리/액션 타입/target_value/auto_claim 여부와 실제 유저 행동 시퀀스)를 알려줘.

ULETTE_TICKET 등)과 V1 호환(ROULETTE_COIN 등) 혼용
  - fallback(티켓 부족 시 V1 코인 차감) 로직이 일부 케이스에서 중복/누락 발생
- 테스트 시나리오에서 V2 티켓과 V1 코인 모두 grant 후 플레이 → ledger에 -1이 1건만 기록되어야 함
- 실제로는 fallback 로직이 불완전하여, V2 티켓이 아닌 V1 코인에서 차감되거나, ledger에 기록이 누락됨

## 3. 핵심 문제
- GameWalletService.require_and_consume_token() 및 각 게임 서비스의 티켓 소비 경로에서 V2/V1 토큰 타입 매핑/우선순위가 일관되지 않음
- fallback(ROULETTE_TICKET → ROULETTE_COIN 등) 시 ledger 기록이 2번 되거나, 아예 기록되지 않는 경우 발생
- 테스트는 "티켓/코인 중 1개만 ledger에 -1 기록"을 기대하나, 실제로는 둘 다 기록되거나, 둘 다 기록되지 않음

## 4. 개선/수정 방향
- V2 표준 토큰 타입(ROULETTE_TICKET, DICE_TICKET, LOTTERY_TICKET) 우선 소비, 부족 시에만 V1(ROULETTE_COIN 등) fallback
- ledger 기록은 실제 차감된 토큰 타입 1건만 남기도록 보장
- require_and_consume_token() 내부에서 fallback 발생 시, ledger 기록이 중복되지 않도록 분기 처리
- 테스트 시나리오에 맞춰 "티켓/코인 중 1개만 -1 기록"이 보장되는지 검증 강화
