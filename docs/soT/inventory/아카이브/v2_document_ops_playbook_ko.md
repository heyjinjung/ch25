## 1. 목적 (Purpose)
현재 docs 내 SoT/learned_/트러블슈팅 문서가 과도하게 분산되어 “무엇이 정본인지, 최신인지, 어디를 봐야 하는지”가 불명확해진 문제를 해결한다.

본 문서는 상용 수준(운영 가능한 수준)의 문서정리 서비스 운영을 위해 아래를 표준화한다.
- 정보구조(IA): 정본(Stable SoT) vs 변경기록(learned_/patch) vs 사건기록(troubleshooting/report)
- 문서 인벤토리화(자동 산출)와 도메인 허브(README)
- 중복 제거/승격 프로세스
- 리다이렉트/아카이브 정책
- 자동 검증(메타/링크/중복)

## 2. 범위 (Scope)
- 대상: `docs/` 전체(특히 `docs/v2_specs/**`)
- 제외: 정책/로직의 내용 변경(문서 “정리/구조/링크/상태”만 다룸)

## 3. 용어 정의 (Definitions)
- **정본(Stable SoT)**: 기능/정책 판단의 최종 기준이 되는 문서(주제당 1개)
- **변경기록(learned_/patch)**: 변경 이유/적용일/영향/검증만 기록하는 누적 문서(정본 대체 아님)
- **사건기록(Troubleshooting/Report)**: 발생 사건 단위 회고(해결되면 링크만 남기고 종료)
- **리다이렉트 스텁(Redirect Stub)**: 문서 이동 시 기존 경로 호환을 위한 “최신 본문 링크만 있는” 파일

## 4. 정보구조(IA) 원칙
### 4.1 정본(Stable SoT)
- 원칙: **주제당 1개**만 존재
- 역할: 구현/운영 판단의 기준
- 요구사항:
  - 상단 메타 블록 유지(문서 타입/버전/작성일/작성자/대상/상태)
  - 최종 검토일/정합성 상태(🟢/🟡/🔴)가 있으면 명시

### 4.2 변경기록(learned_/patch)
- 저장소: `docs/v2_specs/00_sot_meta/00_A_sot_code_ops_chk/learned_/{domain}/`
- 역할: “왜 바뀌었는지/언제 바뀌었는지/무엇이 깨졌는지/어떻게 검증했는지”의 기록
- 정본 승격 규칙(권장):
  - 동일 주제의 learned_가 **3회 이상** 또는 **3일 이상** 누적되면 정본 SoT로 승격 검토
  - 승격 후 learned_ 문서는 “요약 + 정본 링크 + 변경이력”만 남기고 종료

### 4.3 사건기록(troubleshooting/report)
- 원칙: 사건 단위로 기록하고, 정본/변경기록에 반영 완료 시
  - 사건 문서는 “원인/조치/대체 문서 링크”만 남기고 종료
  - 주기적으로 archive로 이동(예: weekly/daily)

## 5. 리다이렉트/아카이브 정책
- 이동/통합 시 기존 경로는 리다이렉트 스텁을 유지한다.
  - 목적: 기존 링크/검색/외부 공유 링크가 깨지지 않도록 함
- Deprecated 문서는 99_archive로 이동하고, 상단에 “대체 문서 1개”를 강제한다.

## 6. 운영 단위(도메인) 표준
- 도메인 예시: auth, user, vault, shop, inventory, level, mission, ops, golden, admin, segment
- 각 도메인은 “도메인 허브(README)”를 갖는다.

### 6.1 도메인 허브(README) 최소 구성
- 정본 SoT 목록(권장 5~15개)
- 최근 30일 변경기록(learned_) 링크
- 자주 깨지는 링크/주의사항
- 운영 점검 체크리스트(선택)

## 7. 문서 인벤토리(자동/반자동) — 1단계
### 7.1 목표
- docs 전체 문서를 스캔해 아래 메타를 표 형태로 산출한다.
  - 경로
  - 문서 타입(SoT/가이드/설계/패치/리포트/인덱스/Redirect)
  - 도메인
  - 버전
  - 작성일
  - 최종 검토일(있으면)
  - 상태(SoT/Deprecated/Redirect 등)
  - 대체 문서 링크(있으면)

### 7.2 산출물(권장)
- `doc_inventory_YYYYMMDD.csv`
- `doc_inventory_YYYYMMDD.md`

## 8. 자동 검증(상용 수준 핵심) — 2단계
최소 3가지는 자동 체크한다.
- 메타 블록 누락/형식 오류
- 링크 깨짐(상대경로 포함)
- 정본 SoT 중복(동일 주제 2개 이상) 의심 탐지

## 9. 단계별 실행 플랜(권장)
### Day 1–2
- 인벤토리 산출 + 도메인 분류표 확정

### Day 3–5
- 도메인 허브(README) 생성 + Top 30 문서만 정본/패치 분리

### Week 2
- 중복 통합/리다이렉트/아카이브 + 링크/메타 자동검증 도입

## 10. 체크리스트 (Done Definition)
- [ ] 인벤토리 리포트가 최신(당일) 기준으로 자동 생성됨
- [ ] 각 도메인 README가 존재하고, 정본/변경기록/사건기록이 분리됨
- [ ] 이동/통합 시 리다이렉트 스텁 정책이 일관되게 적용됨
- [ ] 링크/메타/중복 자동 검증이 최소 1회/일 실행 가능
