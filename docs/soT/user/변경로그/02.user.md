## [쉬운 설명] 지금 충돌되는 영역들: 무슨 기능이고, 왜/어떻게 충돌되는지

### 1. 09:00 KST 리셋 정책 vs 자정 기준 혼용
- **무슨 기능?**: 유저 보상, 미션, 금고 등에서 '하루가 언제 끝나는지' 기준을 정함. 어떤 기능은 '자정(00:00)'에, 어떤 기능은 '아침 9시(09:00)'에 리셋됨.
- **왜/어떻게 충돌?**: 같은 유저라도 어떤 보상은 자정에, 어떤 보상은 9시에 초기화되어 혼란이 생김. 예를 들어, 미션은 9시에 리셋되는데 금고는 자정에 리셋되면, 유저가 언제 다시 받을 수 있는지 헷갈림.

### 2. benefits_suspended(제재) 필드: DB에 없음, 계산식으로만 존재
- **무슨 기능?**: 유저가 7일 동안 입금이 없으면 '제재' 상태가 됨. 이걸 benefits_suspended라고 부름.
- **왜/어떻게 충돌?**: DB에 이 값이 저장되어 있지 않고, 매번 코드를 실행할 때마다 계산함. 그래서 정책/DB/코드/프론트가 서로 다르게 인식할 수 있고, 운영자가 직접 확인하기 어려움.

### 3. 세그먼트 배치 동기화 누락
- **무슨 기능?**: 유저를 등급(세그먼트)별로 나누는 작업을 '배치'라는 프로그램이 정기적으로 실행해서 업데이트함.
- **왜/어떻게 충돌?**: 배치가 제대로 실행되지 않거나, DB에 값이 잘못 저장되면 유저 등급이 실제와 다르게 표시됨. 등급에 따라 혜택이 달라지기 때문에, 잘못 동기화되면 잘못된 혜택이 지급될 수 있음.

### 4. PK/UNIQUE/INDEX 불일치
- **무슨 기능?**: 유저를 구분하는 ID(번호)나, 중복되면 안 되는 값(닉네임, 외부ID 등)에 대해 '중복 금지' 규칙을 DB에 설정함.
- **왜/어떻게 충돌?**: 이 규칙이 빠지거나 잘못 적용되면, 같은 유저가 여러 번 가입되거나, 데이터가 꼬여서 장애가 발생함.
