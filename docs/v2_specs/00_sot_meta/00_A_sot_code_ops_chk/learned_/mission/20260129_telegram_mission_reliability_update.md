# 20260129 텔레그램 미션 신뢰성 최적화 업데이트

## 배경
텔레그램 채널 가입 및 공유(스토리/링크) 미션 시 보상 누락 및 운영 에러가 자주 발생함에 따라, 신뢰성 있는 트리거와 검증 기준을 정립하고 코드로 구현함.

## 기술적 변경 사항 (Learned Logic)

### 1. 정확한 트리거 공식 (Trigger Mapping)
미션의 `action_type`에 따라 텔레그램 네이티브 SDK를 정확하게 연동함.

| 미션 유형 | 정확한 트리거 (SDK) | 보상 기록 시점 |
| :--- | :--- | :--- |
| **채널 가입** | `tg.openTelegramLink(url)` | 가입 후 앱 복귀 시 **"확인하기" 버튼 클릭** |
| **스토리 공유** | `tg.shareToStory(img, text)` | 공유 기능 호출 즉시 (Trust-based) |
| **링크 공유** | `tg.openTelegramLink(share_url)` | 공유 기능 호출 즉시 (Trust-based) |

- **핵심 패턴**: 채널 가입은 `참여 -> 앱 복귀 -> 확인`이라는 명확한 2단계 가이드를 UI에 적용하여 유저가 스스로 검증 프로세스를 완료하도록 유도함.

### 2. 백엔드 검증 및 멱등성 보장
- **서버 검증**: 채널 가입의 경우 `getChatMember` API를 통해 실시간 멤버십 상태(`creator`, `administrator`, `member`, `restricted`)를 확인한 후 보상을 지급함.
- **중복 지급 방지**: `update_progress` 호출 전 `is_completed` 상태를 사전 체크하여 보상이 중복 지급되지 않도록 방어 로직 강화.
- **운영 로그**: `[VIRAL_VERIFY]` 태그를 사용하여 Telegram API의 응답 결과(성공/실패 원인)를 상세히 로깅함.

## 관리자 대응 가이드
- 유저 문의 시 **백엔드 로그**에서 해당 유저의 `telegram_id`와 `VIRAL_VERIFY` 태그를 검색하여 실제 텔레그램 API가 반환한 에러 원인(예: 봇 차단, 미가입 상태 등)을 즉시 확인할 수 있음.
- 공유 미션은 기술적 한계(Telegram의 성공 콜백 부재)로 인해 '신뢰 기반'으로 버튼 클릭 시 지급됨을 인지해야 함.

## 향후 관리 포인트
- `JOIN_CHANNEL` 미션의 경우, 반드시 `MissionCard`에서 **수동 확인 버튼**이 활성화되어야 함을 미션 생성 시 가이드 할 것.
- 텔레그램 SDK 버전 업데이트 시 `shareToStory` 등의 함수의 리턴값이 추가되는지 지속적으로 모니터링할 것.
