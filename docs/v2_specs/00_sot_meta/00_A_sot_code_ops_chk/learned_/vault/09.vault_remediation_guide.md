## Triage Summary ✅
- Priority (high → low):
  1. Admin API / List/DTO에서 `vault_balance = locked + available` 사용 (즉시 수정 권장)
  2. Dashboard 집계 `total_vault_balance`가 `(locked + available)` 기준 (리포트/지표 영향)
  3. Withdrawals 엔드포인트 중복 (운영 혼선)
  4. Admin prefix 혼재(`/admin/api` vs `/api/v2/admin`)
  5. FE 호환 어댑터 `availableBalance` 노출
  6. Enum/상수 표현 드리프트

## Root Cause Hypotheses
- 표현 SoT(what `vault_balance` means) 문서화 미비 → 하위 레이어가 합산 전제로 구현
- 레거시 호환 코드 및 어댑터가 값을 노출하여 혼선 야기
- 상수/Enum이 분산되어 문자열 케이스·타입 불일치 발생

## Remediation Tasks (항목별 상세 가이드)

### A. Admin user list / `vault_balance` 합산 제거 (우선 작업)
- Files to change:
  - `app/v2/api/admin/user_routes.py`
  - DTOs used for admin user list (where `vaultBalance` set)
  - Optional: `app/v2/schemas/admin_user.py` (response schema)
- Code change (example):
```py
# BEFORE (pseudocode)
user.vault_balance = int(user.vault_locked_balance or 0) + int(user.vault_available_balance or 0)
# AFTER
user.vault_balance = int(user.vault_locked_balance or 0)  # canonical source
# Consider renaming to vault_locked_balance or adding deprecation note in openapi
```
- DB: no destructive migration. Optional: create read-only view for canonical vault value.
  - Example view (Postgres/MySQL compatible syntax):
```sql
CREATE OR REPLACE VIEW v2_user_vault_view AS
SELECT id AS user_id, vault_locked_balance AS vault_locked_balance
FROM `user`;
```
- Tests:
  - Unit: `tests/v2_tests/admin/test_user_routes.py::test_list_sort_by_vault_locked_only`
  - Integration: assert API response `vaultBalance` equals DB `vault_locked_balance` for sample users.

- Ops checklist:
  - Pre-deploy: run `SELECT COUNT(*) FROM user WHERE vault_available_balance IS NOT NULL AND vault_available_balance != 0;` attach CSV sample (top 100 rows)
  - Post-deploy: sample 100 user entries from admin list and compare values; raise alert if mismatch.
- Rollout: feature-flag `feature.vault_locked_only_admin_list` toggle (default OFF → roll to ON after smoke tests)

## Alembic Migration Templates
- Create migration to **add view** or **backfill metric table** (safe non-destructive):
```py
# alembic revision -m "create v2_user_vault_view"
from alembic import op
import sqlalchemy as sa

def upgrade():
    op.execute("CREATE OR REPLACE VIEW v2_user_vault_view AS SELECT id AS user_id, vault_locked_balance AS vault_locked_balance FROM `user`;")

def downgrade():
    op.execute("DROP VIEW IF EXISTS v2_user_vault_view;")
```
- For enum normalization use safe UPDATE with logging and small batch window.
