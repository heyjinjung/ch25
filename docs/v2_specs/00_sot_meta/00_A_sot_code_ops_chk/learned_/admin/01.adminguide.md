### 2) Global Circuit Breaker (Payout Safety) ⛔
**Purpose / Impact:** block payout storms and risky mass-grant events; protect vault balance.

**Files to touch / add:**
- `app/v2/services/vault2_service.py` (payout hooks)
- `app/services/circuit_breaker.py` (new helper)
- `alembic/versions/` (new migration to add `v2_global_circuit_breaker` table)
- Admin API: `app/v2/api/admin/ops_routes.py` (reset/trip status endpoints)

**Sample Migration (outline):**
```sql
CREATE TABLE v2_global_circuit_breaker (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  `key` VARCHAR(128) NOT NULL,
  window_seconds INT NOT NULL,
  limit_amount BIGINT NOT NULL,
  current_amount BIGINT NOT NULL DEFAULT 0,
  is_tripped BOOLEAN NOT NULL DEFAULT FALSE,
  last_reset_at DATETIME,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL
);
```

**Implementation notes:**
- Use Redis (atomic INCR + EXPIRE or LUA) for high throughput counter; mirror state to DB for audit.
- Implement `check_and_increment_global_limit(key, amount)` that returns (ok: bool, reason:string).
- On trip: write `v2_ops_execution_result` and `admin_audit_log`, send PagerDuty/Slack alert.
- Provide admin endpoint `POST /api/v2/admin/ops/reset_circuit`.

**Tests:**
- `tests/test_circuit_breaker.py` (including concurrency simulations)
- Load test script in `scripts/` to verify in staging

**Oper Checklist:**
- Define initial limits per `kind` in DB via migration seed.
- Alerting setup (Slack + PagerDuty), add dashboard panels.

**Rollback:** set limits to very high values or disable check flag via feature flag/config.
