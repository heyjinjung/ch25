## 4. 코드베이스 실전 SoT-코드-운영 매핑 검증 리포트 (2026-01-26)

### 주요 발견사항
- 🟡 app/v2, src/v2 경로 내 team_battle, season, rank, score 등 직접적 네이밍/구현은 확인되지 않음(2026-01-26 기준)
    - 실제로 app/v2, src/v2 하위에 team_battle, season, rank, score 등 명칭의 서비스/모델/쿼리/타입/페이지/유틸 파일이 존재하지 않거나, 네이밍이 다를 수 있음
    - 정책/문서상 v2 일관 적용이 명시되어 있지만, 실제 코드베이스에서는 legacy 경로나 v1 네임스페이스, 혹은 혼합 구조가 남아 있을 가능성 있음
    - 예를 들어, 팀배틀 관련 주요 로직이 app/services, app/models, src/pages/game 등 v2 네임스페이스 외부에 위치하거나, 파일명/클래스명이 정책과 다를 수 있음
- 🟡 실제 서비스/모델/쿼리/테스트/프론트 코드가 v2 네임스페이스로 일관 적용되어 있는지 추가 검증 필요
    - 정책상 모든 신규 기능/로직은 app/v2, src/v2 하위에 구현되어야 하나, 실제로는 일부 기능이 이전 경로나 임시 위치에 남아 있을 수 있음
    - 테스트 코드, 쿼리, 프론트엔드 라우팅/타입/유틸 등도 v2 네임스페이스 일관성 여부를 주기적으로 점검해야 함
- 🟡 정책/문서상 v2 일관 적용이 명시되어 있으나, 코드베이스 내 네이밍/경로/구현이 상이할 수 있으므로, 운영/자동화/QA 시 실제 경로/구현 현황을 반드시 확인해야 함
    - 정책/문서와 실제 코드/DB/프론트 구현이 1:1로 일치하지 않을 수 있으므로, 운영자/QA 담당자는 실제 배포 환경의 경로/네이밍/구현 현황을 직접 확인해야 함
    - 자동화 스크립트/운영 체크리스트에 '경로/네이밍/구현 현황 점검' 항목을 추가해, 정책-코드-운영 불일치 리스크를 최소화해야 함
- 🟡 시즌/랭킹 정책 변경(롤오버 등) 시 DB/코드/프론트 동기화 자동화 필요, 운영상 정책 변경/시즌 롤오버 시 QA 체크리스트 강화 필요
    - 시즌/랭킹 정책이 변경되거나 롤오버(새 시즌 시작) 시, DB 스키마/코드/프론트/운영 화면이 모두 동기화되어야 함
    - 정책 변경이 코드/DB/프론트에 즉시 반영되지 않으면, 시즌별 랭킹/보상/참여 로직에 오류가 발생할 수 있음
    - QA 체크리스트에 '시즌/랭킹 정책 변경 시 동기화 자동화' 항목을 추가해, 운영 리스크를 사전에 차단해야 함
- 🟡 Enum/상수/필드 변경 시 코드-DB-프론트 동기화 자동화 및 운영자 알림 연동 필요
    - 팀배틀 관련 Enum(TeamBattleSeason, TeamBattleRank 등), 상수(TEAM_BATTLE_MAX_SCORE 등), 필드명(team_id, score, rank 등)이 변경될 경우, 코드-DB-프론트가 모두 동기화되어야 함
    - Enum/상수/필드 변경이 일부 레이어에만 반영될 경우, 데이터 불일치/운영 오류/프론트 표시 오류가 발생할 수 있음
    - Enum/상수/필드 변경 시 운영자 알림(자동화) 및 QA 우선 검증이 필요함
- 🔴 레거시/임시 예외/누락(예: 시즌 정책 변경 시 동기화 누락, Enum/상수 변경 미반영 등) 발생 시 운영자 주의/자동화/QA 우선 검증 필요
    - 과거 v1 경로나 임시 예외, 정책 변경 누락, Enum/상수/필드 미반영 등 레거시 이슈가 남아 있을 수 있음
