## 3. 정합성 검증 요약 리포트 (Step 2-2)

- **상태**: 🟡 **업데이트 필요 (Step 2-3: Golden V2/티켓 정책 반영)**
- **주요 발견 사항**:
    - 🔴 [정책/구현 충돌]: **보상 저장소 분기**. `GameWallet`(TICKET/DIAMOND)과 `Inventory`(GIFTICON)의 적재 로직이 `RewardService` 레벨에서 정확히 분기되는지 Cross-Check 필요.
    - 🔴 [DB/코드 정합]: **룰렛 Grade 폐기**. DB `v2_roulette_config.grade`는 존재하나 코드/기획에서는 Deprecated됨. Admin UI에서 완전히 제거되었는지 확인 필요.
    - 🟡 [정합성 검토 필요]: **Admin API Enum**. 프론트엔드가 `reward_type` (snake_case)과 `rewardType` (camelCase)를 혼용하는 경우가 있어 표준화 필요.
    - 🟢 [성공]: **룰렛 8-segment**. DB Constraint(`0~7`)와 프론트엔드 렌더링 로직(8조각)이 일치함. Figma 로컬 에셋 기반 구현 정책 준수 확인됨.
- **조치 사항**: 1) `RewardService` 저장소 분기 단위테스트 강화, 2) 프론트엔드 API 타입 정의(`interface`) 전수 조사를 통한 케이스 통일.

## 4. 코드베이스 실전영역 체크 리포트 (Step 3-3)

- **검증 일시**: 2026-01-26
- **검증 대상**: `app/v2/services`, `src/v2/api`, `app/v2/models`
- **주요 발견 사항**:
    - 🔴 **[운영 누락] Golden V2 Circuit Breaker**: SoT(`golden_v2_operational_logic_ko.md`)에는 "Global Limit", "Error Rate Pause" 등 서킷 브레이커가 필수 안전장치로 명시되어 있으나, 실제 `golden_intervention_service.py` 및 전체 코드베이스 내 구현체 없음. **긴급 구현 필요.**
    - 🟡 **[API 혼용] Case Mismatch**: 
        - Game API (`RouletteStatusResponse` 등) -> `snake_case` (e.g., `max_daily_spins`)
        - Vault API (`VaultStatusResponse`) -> `camelCase` (e.g., `vaultBalance`)
        - Frontend `gameApi.ts`에서 이를 각각 다르게 정의하여 사용 중. 장기적으로 `camelCase` 표준화 권장.
    - 🟢 **[구현 정합] Reward Separation**: `RewardService.deliver` 메서드에서 `TICKET`(Wallet)과 `GIFTICON`(Inventory)을 `token_type` 및 `RewardService._grant_*` 메서드로 정확히 분기 처리하고 있음. `V2AdminInventoryService` 레벨에서도 테이블 분리가 확인됨.
    - 🟢 **[정책 정합] Ticket Conversion**: `V2TicketConversionPolicy` 모델이 `ratio_numerator/denominator` Default=1로 설정되어 있어, 1:1 변환 정책을 DB 스키마 수준에서 지원함.
    - 🟡 **[스키마 잔존] Roulette Grade**: `V2RouletteConfig` 테이블에 `grade` 컬럼이 `NOT NULL Default 'COMMON'`으로 남아있음 (SoT는 Deprecated). 코드 레벨에서는 `get_status` 등에서 Fallback 로직으로 사실상 무시하고 있어 운영상 치명적이지 않으나 스키마 정리 필요.

- **종합 의견**: 게임 엔진 로직과 데이터 분리 정책은 잘 지켜지고 있으나, **Golden V2의 운영 리스크 관리 기능(안전장치)**이 누락되어 있어 배포 전 구현이 필수적임.

## 5. 알기 쉬운 불일치 설명 (For Beginners)

이 섹션은 위에서 발견된 복잡한 문제들을 **중학생도 이해할 수 있도록** 쉽게 풀어서 설명합니다.

### 🔴 1. Golden V2 서킷 브레이커 누락 (안전장치가 없어요!)
- **무슨 기능인가요?**: 집에 누전차단기(두꺼비집)가 있는 것과 같아요. 전기를 너무 많이 쓰거나 합선되면 자동으로 전기를 끊어서 불이 나는 걸 막아주는 장치예요.
- **무슨 일을 하나요?**: 게임에서 보상 시스템이 고장나서 유저들에게 돈을 무한대로 퍼주기 시작하면, 자동으로 "잠깐 멈춰!" 하고 시스템을 정지시켜서 회사 돈이 다 털리는 걸 막아요.
- **왜 충돌나나요?**: 설계도(문서)에는 "두꺼비집을 꼭 설치하세요"라고 되어 있는데, 실제로 지어진 집(코드)을 보니 두꺼비집이 아예 없어요. 이대로라면 사고 났을 때 큰일 나겠죠? 그래서 **긴급**한 문제예요.

### 🟡 2. API 대소문자 표기법 혼용 (사투리가 섞여 있어요)
- **무슨 기능인가요?**: 서버(백엔드)와 브라우저(프론트엔드)가 대화할 때 쓰는 단어 규칙이에요.
- **무슨 일을 하나요?**: `rewardType`이라고 쓸지, `reward_type`이라고 쓸지 정하는 거예요. 한국어와 영어를 섞어 쓰는 느낌이랑 비슷해요.
- **왜 충돌나나요?**: 어떤 친구(Game API)는 "snake_case"(밑줄) 사투리를 쓰고, 다른 친구(Vault API)는 "camelCase"(대문자) 사투리를 써요. 프론트엔드 개발자가 통역하느라 헷갈릴 수 있어요. 당장 대화가 안 통하는 건 아니지만, 나중엔 하나로 통일하는 게 좋아요.

### 🟡 3. 룰렛 Grade 컬럼 잔존 (이사 갔는데 짐을 안 뺐어요)
- **무슨 기능인가요?**: 예전에는 유저 등급(Grade)에 따라 다른 룰렛을 보여주려고 만든 칸이에요.
- **무슨 일을 하나요?**: 지금은 "티켓 종류"로 룰렛을 나누기로 규칙이 바뀌어서, 이 등급 칸은 더 이상 안 써요.
- **왜 충돌나나요?**: 집주인(코드/기획)은 "이 방 안 써요"라고 했는데, 등기부등본(DB)에는 아직 그 방이 남아있어요. 나중에 헷갈릴 수 있으니 서류 정리를 해주는 게 깔끔하겠죠?
