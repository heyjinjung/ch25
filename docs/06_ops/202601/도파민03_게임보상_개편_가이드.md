## 📌 Executive Summary

### ⚠️ 핵심 제약 조건 (Critical Constraint)

> [!CAUTION]
> **롤링(Rolling) 조건 설정 불가**
> 
> 현재 시스템은 **"외부 랭킹 입금액(TOTAL_DEPOSIT)"**을 CSV로 가져와서 레벨을 부여하고, 레벨에 따라 티켓을 증정하는 구조입니다.
> 
> **플랫폼 내부에 "입금(Deposit)" 개념 자체가 없습니다.**
> 
> 따라서 "입금액 × N% 롤링" 같은 조건을 걸 수 있는 **기준점(Base)**이 존재하지 않습니다.

## 5. 개편 방향: Casino Buy-In 모델

### 5.1. 핵심 컨셉

기존 상점은 **DIAMOND**로만 구매 가능했습니다.  
개편 후에는 **금고 잔액(vault_locked_balance)**으로도 티켓을 구매할 수 있게 합니다.

```
[기존] 금고 잔액 ───▶ 출금 신청 ───▶ (끝)

[개편] 금고 잔액 ───┬──▶ 출금 신청
                   │
                   └──▶ 티켓 구매 (재베팅) ───▶ 게임 ───▶ 금고 적립 (반복)
```

### 5.2. 롤링 효과

| 시나리오 | 유저 행동 | 결과 |
|:---|:---|:---|
| **출금만** | 금고 10,000원 → 바로 출금 | 사이트 이윤 0원 |
| **재베팅** | 금고 10,000원 → 티켓 구매 → 게임 → 패배 | 사이트 이윤 발생 |

### 5.3. 전략적 효과 분석

> [!WARNING]
> **핵심 질문**: "금고 잔액으로 티켓 구입"만으로 도파민 형성 / 체류시간 증가 / 외부사이트 리텐션이 가능한가?

#### A. 기대 효과

| 효과 | 메커니즘 | 실현 가능성 |
|:---|:---|:---|
| **체류시간 증가** | 출금 전에 "한 판 더" 심리 유도 | ⭐⭐⭐ 높음 |
| **재베팅 사이클** | 재미를 느낀 유저는 계속 플레이 | ⭐⭐ 중간 |
| **외부 리텐션** | "첫쵩에 당첨"된 유저가 외부 입금 증가 | ⭐ 불확실 |

#### B. 한계점

| 한계 | 설명 |
|:---|:---|
| **무료로 받은 금고** | 애초에 "공짜로 받은 돈"이라 소비 저항감 낮음 |
| **외부 입금과 분리** | 금고 소진이 외부 입금 동기로 직결되지 않음 |
| **게임 자체 재미** | RTP가 낮으면 유저가 "돈만 잃는다"고 느낄 |

#### C. 효과 극대화 전략

| 전략 | 설명 | 우선순위 |
|:---|:---|:---|
| **보너스 강화** | 10,000원 → 12장 (20%+) 로 "더 이득" 심리 | P0 |
| **잭팟 이벤트** | 티켓 구매 시 5% 확률로 "대박" 기회 | P1 |
| **게임 RTP 상향** | Dice 승리 보상 200원 → 2,000원 | **P0 (필수)** |
| **외부 연계 오퍼** | "오늘 입금하면 여기서 보너스 티켓 10장" | P2 |

> [!IMPORTANT]
> **결론**: "금고 → 티켓" 자체는 필요 조건이지, 충분 조건이 아닙니다.  
> **보너스 + RTP 상향 + 외부 연계 오퍼**가 함께 돌아가야 실제 효과가 나타납니다.

## 7. 기술 구현 계획

### 7.1. 신규 결제 타입 추가

# game_wallet.py
class GameTokenType(str, Enum):
    # ... 기존 ...
    VAULT = "VAULT"  # 금고 잔액 결제용 (신규)

### 7.2. ShopService 결제 분기

> **핵심**: `cost_token`에 따라 어떤 재화에서 차감할지 결정

```python
# shop_service.py - purchase_product()

if product.cost_token == GameTokenType.DIAMOND:
    # 다이아몬드(인벤토리)에서 차감
    InventoryService.consume_item(db, user_id, "DIAMOND", ...)

elif product.cost_token == GameTokenType.VAULT:
    # 🆕 신규: 금고 잔액에서 차감
    VaultService.consume_locked_balance(db, user_id, product.cost_amount)

else:
    # 예: cost_token=ROULETTE_COIN이면 "룰렛 티켓"을 소비
    # → GameWallet의 해당 토큰 잔액에서 차감 (= 티켓 차감)
    GameWalletService().require_and_consume_token(...)
```

> [!NOTE]
> **GameWallet 토큰 차감 = 티켓 차감**  
> `ROULETTE_COIN`, `DICE_TOKEN`, `LOTTERY_TICKET` 등은 모두 "티켓"입니다.  
> `require_and_consume_token()`은 해당 티켓 잔액을 확인하고 차감합니다.

### 7.3. VaultService 신규 메서드

```python
def consume_locked_balance(
    self, db: Session, user_id: int, amount: int
) -> int:
    """금고 잔액 차감 (상점 구매용)"""
    total, reserved, available = self.get_vault_amounts(db, user_id)
    if available < amount:
        raise HTTPException(400, "INSUFFICIENT_VAULT_BALANCE")
    
    user.vault_locked_balance -= amount
    user.vault_spent_total += amount  # 롤링 추적
    self.sync_legacy_mirror(user)
    return amount
```
