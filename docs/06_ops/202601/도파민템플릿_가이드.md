# 📄 도파민 확장 문서 템플릿 가이드 (Template Standard)

**문서 연결**: [도파민sot](./도파민sot.md)
**작성일**: 2026-01-14
**목적**: 모든 도파민 확장 문서(01~06)가 동일한 구조와 깊이로 작성되어, 개발/운영 간 커뮤니케이션 효율을 극대화하기 위함입니다.

---

## 1. 목적 (Objective)
*   **Why**: 왜 이 기능을 만드는가? (도파민/리텐션 관점의 기획 의도)
*   **Goal**: 무엇을 달성하고자 하는가? (정성적 느낌 또는 정량적 목표)

## 2. 유저 시나리오 (User Flow)
*   **Scenario**: 유저가 진입해서 보상을 받기까지의 구체적인 행동 흐름.
    *   (예: 로비 진입 -> 팝업 노출 -> 버튼 클릭 -> 보상 수령 -> 게임 이동)
*   **Core Vibe**: 유저가 느껴야 할 핵심 감정 ("와! 개꿀!", "아깝다!", "한 판만 더?" 등).

## 3. 기존 시스템 분석 (Legacy Analysis)
*   **[활용] 재활용 요소 (Reusable)**: 새로 만들지 않고 가져다 쓸 기존 로직, 테이블, UI 컴포넌트.
*   **[주의] 충돌/변경 지점 (Conflict/Change)**: 기존 로직(Bank Model)과 충돌하거나 불가피하게 수정해야 하는 부분.

## 4. UI/UX 및 연출 (Visuals & Copy)
*   **UI 구성**: 화면 내 배치 위치, 트리거 시점(진입/종료/클릭).
*   **Copywriting (Tone & Manner)**: 버튼명, 알림 멘트, 팝업 문구 등 유저를 꼬시는 텍스트.
*   **Effect**: 강조 효과, 사운드, 애니메이션 등 도파민 자극 요소.

## 5. 기술 구현 가이드 (Technical Scope)
*   **DB Schema**: 테이블 컬럼 추가/변경 사항.
*   **Backend Logic**: API 수정, 핵심 로직 흐름, 데이터 처리 방식.
*   **Frontend Logic**: 상태 관리(Zustand), 데이터 바인딩, 컴포넌트 구조.

## 6. 운영 및 리스크 관리 (Ops & Risk)
*   **Admin Tool**: 운영자가 제어할 수 있어야 하는 기능 (On/Off 스위치, 강제 지급 등).
*   **Risk Point**: 어뷰징 가능성, 시스템 오작동 시 대처 방안.
*   **Measurement**: 로그 적재 및 성과 측정 지표 (KPI).
