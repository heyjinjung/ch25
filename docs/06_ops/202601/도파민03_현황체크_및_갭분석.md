## 2. 게임별 보상 및 순환 구조 분석 (Game Loop Analysis)

### 2.1. 🎲 다이스 (Dice)
*   **Betting (Input)**: `DICE_TOKEN` (GameWallet)
    *   *Source*: 상점에서 `DIAMOND`로 교환하거나 미션 보상으로 획득.
*   **Winning (Output)**: `POINT` -> **`Vault Locked Balance`** (via `VaultService.record_game_play_earn_event`)
*   **Friction Analysis (Gap)**:
    *   유저는 토큰을 써서 포인트를 얻음.
    *   포인트는 **잠긴 금고(Vault Locked)**로 들어감.
    *   **재베팅 불가**: 얻은 포인트를 즉시 `DICE_TOKEN` 구매에 쓸 수 없음 (상점은 `DIAMOND` 요구, 포인트->다이아 환전 경로 불명확).
    *   *Result*: "돈을 땄는데 쓸 곳이 없고 잠겨있음" -> 흥미 반감.

### 2.2. 🎡 룰렛 (Roulette)
*   **Betting (Input)**: `ROULETTE_COIN` (GameWallet)
*   **Winning (Output)**:
    *   `POINT`: **`Vault Locked Balance`**
    *   `DIAMOND/XP`: Inventory/SeasonPass (즉시 지급)
*   **Friction Analysis (Gap)**:
    *   포인트 당첨 시 금고로 직행.
    *   재베팅을 위해서는 [금고 출금 -> 포인트로 코인 구매] 과정이 필요하나, 현재 상점(`ShopService`) 기본 품목은 `DIAMOND` 재화만 요구함.
    *   *Note*: 포인트로 티켓/코인을 사는 상품(`PROD_TICKET_COIN_1` 등)의 구매 재화가 `DIAMOND`로 설정되어 있음.

### 2.3. 🎟️ 복권 (Lottery)
*   **Betting (Input)**: `LOTTERY_TICKET` (GameWallet)
*   **Winning (Output)**: `POINT` -> **`Vault Locked Balance`**
*   **Friction Analysis (Gap)**:
    *   다이스/룰렛과 동일 구조. 당첨금이 즉시 유동성(Liquidity)을 제공하지 못함.

## 3. 주요 서비스 분석 (Service Level Analysis)

### 3.1. RewardService & VaultService
*   **현황**: `RewardService.deliver(reward_type="POINT")` 호출 시 `_grant_vault_locked()`를 통해 무조건 **잠긴 잔액**으로 적립됨.
*   **Admin Grant**: 관리자가 지급하는 보상(`AdminGameRewardService`) 역시 동일한 경로를 따름. 관리자가 "보너스"를 줘도 유저는 "출금 전까지 못 쓰는 돈"을 받게 됨.
*   **문제점**: "금고에서 돈을 빼서 쓴다"는 유저 멘탈 모델은 맞지만, **게임 승리금까지 강제로 금고에 넣고 잠그는 것**이 템포를 끊음.

### 3.2. ShopService (상점)
*   **현황**: 상품(`ShopProduct`)들의 비용(`cost_token`)이 대부분 **`DIAMOND`**로 하드코딩 되어 있음.
*   **Gap**: 게임 승리 보상은 `POINT`인데, 게임 티켓 구매는 `DIAMOND`를 요구함. `POINT` -> `DIAMOND` 환전처가 없으면 경제 순환(Economy Loop)이 끊어짐.

### 3.2. ShopService (상점) 및 경제 구조 딜레마
*   **현황**: 상품들의 구매 비용이 `DIAMOND`로 설정됨. `DIAMOND`는 외부 환전이 불가능한 '게임 머니' 성격.
*   **User Dilemma**:
    *   유저는 `POINT`(=현금 가치)를 따서 외부로 환전하는 것을 선호함 (매력도 High).
    *   기존에는 이를 복잡하게 하려고 `DIAMOND` 단계를 넣었으나, 오히려 **"땄는데 쓸 곳이 없다"**는 부정적 경험(Friction)이 되어버림.
    *   재베팅을 유도하려면 `POINT`를 다시 게임에 넣게 만들어야 함.

## 4. 해결 방향 및 아이디어 (Proposed Solution & Ideas)

**"카지노 칩 교환소 (Casino Buy-In Model)" 도입**

가장 직관적이고 강력한 도파민 루프는 **"내가 번 돈(POINT)으로 다시 칩(Ticket)을 산다"**는 감각입니다.

### 4.1. 상점의 이원화 전략 (Dual Currency Shop)
"다이아를 없애는 것"이 아니라, **"포인트로도 살 수 있게"** 문을 여는 것입니다.

1.  **메인 루프 (Cash Flow)**: **`POINT` -> `Ticket` 직접 구매 허용**
    *   *Concept*: 카지노 입구에서 현금(POINT) 내고 칩(Ticket) 받는 것과 동일.
    *   *Effect*: 유저가 "출금할까? 아니면 이 돈으로 티켓 사서 대박 노릴까?"를 **즉시 고민**하게 만듦 (재베팅 유도 최적화).
    *   *Implementation*: 상점 상품에 `cost_token="POINT"`인 버전 추가. (예: `티켓 1장 = 1,000 P`)

2.  **다이아의 역할 재정의 (Loyalty/Bonus)**:
    *   다이아는 **"게임하다 보면 쌓이는 보너스 마일리지"**로 포지셔닝.
    *   용도: 특수 아이템(Gold Key), 스킨, 또는 '현금으로 사기 아까운' 버프 아이템 구매.
    *   *Value*: 유저에게 "공짜로 얻은 재화"라는 느낌을 주어, 부담 없이 쓰게 만듦.

### 4.2. 기대 효과
*   **Turnover 증가**: 출금(Exit)하려는 유저를 상점(Re-bet)으로 낚아챌 수 있는 가장 확실한 미끼는 "지금 가진 돈으로 바로 티켓 구매"입니다.
*   **복잡성 해소**: "포인트를 다이아로 바꿔서... 티켓을 산다"는 2단계를 1단계로 단축.
*   **외부 환전 매력도 유지**: 포인트는 여전히 "현금 가치"를 유지하므로, 땄을 때의 쾌감(Real Money Win)은 그대로 유지됨.

### 4.3. 실행 과제 (Action Item)
1.  **Shop Data**: 상점(`ShopService`)에 `cost_token`이 `POINT`인 티켓 상품군 추가 (기존 다이아 상품과 병행).
2.  **Seed Data**: 신규 유저 미션 보상을 `2,500 P` -> `Rulelte Coin 5개`로 변경 (즉시 게임 경험 제공).








### 3.3. 신규 유저 미션 (`seed_new_user_missions.py`)
*   **현황**: 4개 미션 보상이 모두 `2,500 KRW (Vault Locked)`로 설정됨.
*   **Gap**: "티켓 5장"이라는 기획 의도와 달리, 유저는 활용성 낮은 잠긴 포인트만 받게 되어 초기 이탈 요인이 됨.

## 4. 해결 방향 (Proposed Solution Path)
**"Unified Economy SOT 준수"**:
1.  **Money SOT 유지**: `POINT` 리워드는 무조건 `Vault Locked Balance` (금고)로 적립됩니다.
    *   *SOT Definition*: "POINT"는 보상 타입 명칭이며, 실제 자산은 "금고 잔액(Money)"입니다. `cash_balance`는 Legacy로 폐기합니다.
2.  **Casino Buy-In (Shop Upgrade)**:
    *   `ShopService`에서 `cost_token=POINT`는 **`VaultService.consume_locked_balance` (금고 잔액 차감)**로 매핑됩니다.
    *   *Effect*: 유저는 "금고에 있는 돈"을 사용하여 즉시 티켓을 구매합니다. (출금 프로세스 불필요)
3.  **Seed Data Fix**:
    *   신규 유저 미션 보상을 `ROULETTE_COIN` 5개로 DB 데이터 수정.

## 5. 마케팅/경제 전략 제언 (Strategic Proposal: Why Re-bet?)

유저의 의문(출금 vs 재베팅)을 해소하기 위해, **"금고 잔액(Money)의 구매력을 현금 인출 가치보다 높이는(Value Multiplier)"** 전략이 필수적입니다.

### 5.1. 벌크 보너스 (Bulk Discount) - "묶음이 더 싸다"
*   **개념**: 현금 10,000원은 티켓 10장이지만, 금고 잔액 10,000원은 티켓 **12장**입니다.
*   **심리**: "지금 환전(Withdraw)하면 10,000원이지만, 다시 걸면(Re-bet) 12,000원어치 기회다."
*   **구현**: `ShopService` 패키지 상품(`PROD_TICKET_10`)의 효율을 120%로 설정.

### 5.2. 컴프(Comps) 시스템 - "쓰는 만큼 대우받는다"
*   **개념**: 금고 잔액을 소각(Spend)할 때마다, 비매품 재화인 **`DIAMOND`**를 페이백(Cashback)으로 지급.
*   **심리**: "출금하면 돈만 받지만, 재베팅하면 돈(티켓) + 명예(다이아)를 다 얻는다."
*   **구현**: `ShopService` 구매 완료 시 `InventoryService.grant_item(DIAMOND)` 훅 트리거.

### 5.3. 럭키 드로우 (Lucky Purchase) - "구매도 도박이다"
*   **개념**: 금고 잔액으로 티켓 구매 시, 5% 확률로 **"황금 티켓(Golden Key)"** 등 상위 아이템 획득.

### 5.4. RTP (Return To Player) 긴급 분석 결과 (2026-01-14)
*   **Dice**: 1,000원 티켓 대비 승리 보상 200원 -> **RTP 7.2% (심각)**. 5배 상향 필요.
*   **Roulette**: **RTP 66.25%**. 100/200/500원 비중이 높음. 상향 필요.
