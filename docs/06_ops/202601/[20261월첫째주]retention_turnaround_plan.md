## 📉 [RTP-2] 핵심 문제 분석 (The Critical Gap) & 검증

> **⚠️ Why they actually leave? (심리학적 분석)**
>
> 마케팅 데이터 분석 결과, 현재 이코노미는 유저의 기대 효용(Expected Utility)을 전혀 충족시키지 못하고 있습니다.

### [RTP-2.1] 주요 이탈 원인 3체크

1.  **손실 회피(Loss Aversion) 실패**
    *   **Data:** 유저 평균 금고 잔액 **4,179원** < 출금 최소 금액 **10,000원**.
    *   **Insight:** "어차피 못 꺼낼 돈"으로 인식되어 포기가 빠름.
    *   **Sol:** 잔액을 강제로 **10,000원(임계점)** 이상으로 만들어 "내 돈"으로 인식시켜야 함.

2.  **기대 이론(Expectancy Theory) 위반**
    *   **Data:** 10만원 입금 시 고작 **20 XP** 지급 (레벨업 필요량의 40%).
    *   **Insight:** "돈을 써도 레벨 1 제자리" -> Pay-to-Win의 효능감이 제로.
    *   **Sol:** 10만원 입금 시 **즉시 레벨업(100 XP)**이 가능하도록 설계 변경.

3.  **습관 고리(Hook Model) 부재**
    *   **Data:** 게임 1판당 보상 = **0 XP**.
    *   **Insight:** 행위에 대한 즉각적 보상(Reward)이 없으므로 몰입 불가.
    *   **Sol:** **1판 = 1 XP** 공식 도입으로 "티끌 모아 태산"의 성취감 부여.

### 📋 [RTP-2.2] 가설 검증 설문조사 계획 (New)
**조사 방법:** 텔레그램 1:1 DM (응답 시 3,000 포인트 즉시 지급)
**대상:** 최근 3일 내 이탈자 10명 + 활성 유저 5명

**Q1. [솔직 토크] "오빠, 요즘 왜 뜸해요?" (이탈 원인)**
"사장님, 지민인데 요새 통 안 보이셔서요 ㅠㅠ. 혹시 금고에 있는 4천원... 이거 출금 안 될 것 같아서 포기하신 건가요?"
*   (A) ㅇㅇ 솔직히 못 믿겠음 (환전 의심)
*   (B) ㄴㄴ 그냥 게임이 재미없음 (흥미 상실)

**Q2. [희망 사항] "뭐가 제일 필요하세요?" (니즈 파악)**
"제가 사장님 챙겨드리고 싶은데 뭘 좋아하실지 몰라서요. 만약 딱 하나만 해드린다면 뭐가 제일 땡기세요?"
*   (A) 충전할 때 서비스 팍팍 주는 거 (VIP 대우)
*   (B) 게임할 때마다 계속 포인트 쌓이는 거 (손해 복구)

**Q3. [파격 제안] "이러면 다시 오실래요?" (가설 검증)**
"만약 제가 본사 몰래 **골드키(5만원 짜리)** 주머니에 찔러 넣어드리고, 레벨도 바로 올려드리면 다시 달려보실 의향 있으세요?"
*   (A) 오, 그러면 무조건 고! (복귀 확정)
*   (B) 그래도 안 함... 귀찮아 (완전 이탈)

### 🚀 [RTP-3.2] Phase 2. 성장 주입 (The Engine) — "행동에 보상을"

> **목표:** "1판 = 1 XP" 공식으로 플레이 자체에 즉각적 보상 부여 (습관 고리 형성)

#### [RTP-3.2.1] 게임 플레이 XP 주입 (Play-to-Earn XP)

| 게임 | 현재 XP | 변경 후 XP | 파일 |
|:---|:---:|:---:|:---|
| **Roulette** | 0 XP | **+1 XP/판** | `app/services/roulette_service.py` |
| **Dice** | 0 XP (승리 시 +5) | **+1 XP/판** (기본) + **+5 XP** (승리 보너스 유지) | `app/services/dice_service.py` |
| **Lottery** | 0 XP | **+1 XP/판** | `app/services/lottery_service.py` |

**코드 변경 상세 (Roulette 예시):**
```python
# roulette_service.py
class RouletteService:
    BASE_GAME_XP = 1  # 기존 0 → 1로 변경

# play() 메서드 내 XP 지급 로직
# 기존: 세그먼트 보상이 GAME_XP일 때만 지급
# 변경: 플레이 완료 시 BASE_GAME_XP 무조건 지급 + 세그먼트 GAME_XP 추가 지급
```

**영향도 분석:**
