## 2. Layer 2: Golden Hour (Hot Time)

### 2.1. 골든아워 기본 설정

**시간**: 매일 20:00 - 21:00 (1시간)  
**목표**: CCU 2배 + 티켓 소비 3배

**효과**:
| 게임 | 기본 | 골든아워 |
|:---|:---:|:---:|
| 주사위 (COMMON) | +1000/+100/-100 | +2000/+200/-200 |
| 주사위 (VIP) | +2000/+200/-100 | +5000/+500/-200 |
| 기본 룰렛 | 꽝 30% | 꽝 15% |
| 골드 룰렛 | 잭팟 2% | 잭팟 5% |

**구현**:
```python
# DiceService.py
def get_reward_multiplier(user_segment, is_golden_hour):
    if is_golden_hour:
        if user_segment == "WHALE" or user_segment == "VIP":
            return 2.5  # 250%
        elif user_segment == "COMMON":
            return 2.0  # 200%
    return 1.0
```

## 3. Layer 3: 위기 개입 (Crisis Intervention)

> [!NOTE]
> 11대 위기 시나리오는 [도파민AA202601_event_ops_plan](./도파민AA202601_event_ops_plan_implementation_guide.md) 참조

### 3.1. Ticket-Zero 위기 (도파민04 연동)

> [!IMPORTANT]
> [도파민04 4.2] Ticket-Zero 2단계 처리 적용

**티켓 정의** ([도파민04 4.2]):
```
"플레이 가능 티켓" = ROULETTE_COIN + DICE_TOKEN + LOTTERY_TICKET + TRIAL_TOKEN
프리미엄 키 (GOLD_KEY, DIAMOND_KEY) = "입장권"이지만 구제 대상 제외
```

**SoT**:
- Wallet: `user_game_wallet` (GameTokenType별 balance)
- Ledger: `user_game_wallet_ledger` (reason/label/meta)
- Vault: `user.vault_locked_balance`

---

#### Scenario A: 티켓 0 + 금고 잔액 있음 (우선)

**조건**:
```python
# 현재 서버 로직 (vault_service.py)
ticket_count = DICE_TOKEN + ROULETTE_COIN + LOTTERY_TICKET  # 3종
vault_balance = user.vault_locked_balance

if ticket_count == 0 and vault_balance > 0:
    return "OPEN_VAULT_MODAL"
```

**자동 개입** ([도파민04 4.2]):
```
[팝업] "티켓이 0장입니다. 보관금으로 바로 한 판 더 가능해요"
[CTA] "티켓 채우러 가기"
[도파민03 Buy-in 연결] → 금고→티켓 구매 화면
```

**API**:
- `GET /api/vault/status` → `recommended_action=OPEN_VAULT_MODAL`
- [도파민03] `POST /api/shop/purchase` (token_type=VAULT)

**[도파민04 5.2] 확장 계획**:
> Ticket-Zero의 기본 해법을 "무료 지급"이 아니라 **"금고→티켓(Buy-in)"**로 두고,  
> 금고도 0일 때만 Trial Grant를 사용하도록 UX 설계

---

#### Scenario B: 티켓 0 + 금고도 0 (구제)

**조건**:
```python
if ticket_count == 0 and vault_balance == 0:
    return "TRIAL_GRANT"
```

**[도파민04 5.2] Trial Grant 시스템 (현행)**:
```
[모달] "심폐소생술 들어갑니다! ⚡"
[CTA] "체험 티켓 받기"
[연출] 긴급 구조대(응급키트) 느낌 + 토큰 "부활" 애니메이션
```

**API**: `POST /api/trial-grant`  
**서비스**: `TrialGrantService.grant_daily_if_empty()`

**제한사항** ([도파민04 5.2]):
- **일일 cap**: 3장 (전체 trial-grantable 토큰 합)
- **주간 cap**: 환경 변수로 튜닝 가능
- **2회차 이후**: 지급 확률 감소 (남용 방지)
- **Ledger**: `user_game_wallet_ledger` (reason=`TRIAL_GRANT`)
- **안전장치**: 프리미엄 키(`GOLD_KEY`, `DIAMOND_KEY`) 자동 지급 금지

**[도파민04 6] Admin 조정**:
- 일일 cap / 주간 cap / 2회차 확률 조정 가능
- Trial Grant는 ledger 기반 멱등 처리
- Frontend 모달 throttle (30분) 권장

### 6.2. Backend API

```python
# EventService.py
class EventService:
    def is_golden_hour(self) -> bool:
        now = get_server_time()
        config = get_event_config("GOLDEN_HOUR")
        return config.is_active and config.start_time <= now.time() <= config.end_time
    
    def get_multiplier_for_segment(self, user_segment: str) -> float:
        if not self.is_golden_hour():
            return 1.0
        
        multipliers = {
            "WHALE": 2.5,
            "VIP": 2.5,
            "COMMON": 2.0,
            "AT_RISK": 1.0
        }
        return multipliers.get(user_segment, 1.0)
```
