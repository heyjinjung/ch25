# 도파민05 백엔드 구현 계획서 (Events & Operations)

작성일: 2026-01-14  
범위: 도파민05_이벤트_장치_가이드 기준 (Golden Hour / Crisis / Segment Event / Ops Execution)  
전제: 도파민01~04 구현 완료, SoT/정책은 도파민sot 및 Core Economy Glossary 준수

---

## 1) 목표 및 범위

- **Golden Hour 이벤트 체계**: 시간 기반 이벤트 감지 + 세그먼트별 배수 적용
- **Crisis Intervention**: Ticket-Zero/금고 소진/불운 시나리오 자동 감지
- **Segment Campaign**: COMMON/VIP 대상 이벤트 트리거 및 전환 유도
- **Ops 실행 기반**: Admin Ops Plan과 연결 가능한 데이터/토글/로그 제공
- **관측/로그**: 이벤트 참여 및 지급 기록을 일관된 로그로 남김

---

## 2) 단계별 구현 로드맵

### 2.1 데이터 모델 확장

- `event_config` (이벤트 설정)
  - `event_type`, `is_active`, `multiplier`, `start_time`, `end_time`, `target_segment`, `config_json`
  - **기본 시드**: GOLDEN_HOUR(20:00~21:00), SEGMENT 이벤트 기본값
- `event_participation_log` (이벤트 참여/지급 로그)
  - `user_id`, `event_id`, `participated_at`, `reward_*`
- 인덱스
  - `event_config(event_type, is_active)`
  - `event_participation_log(user_id, event_id, participated_at)`

### 2.2 서비스/로직 계층

- `EventService`
  - `is_golden_hour()` (server time 기준)
  - `get_multiplier_for_segment(segment)` (VIP/WHALE/COMMON/AT_RISK)
  - **Golden Hour 배율은 Vault 적립 금액에만 적용** (XP 제외)
- `DiceService` / `RouletteService`
  - 이벤트 배수 적용 지점 표준화 (EventService 사용)
  - 프리미엄 룰렛 접근 제어는 기존 로직 유지
- `CrisisDetectionService`
  - Scenario 1/3/5 조건 쿼리 정의
  - 결과를 `ops_target_list`(또는 기존 Target List)로 적재
- 스케줄러
  - `daily_crisis_detection` (KST 09:00)
  - Golden Hour 시작/종료 시각 기준 캐시 업데이트 (필요 시)

### 2.3 API 설계

- 사용자
  - `GET /api/events/status`
    - `is_golden_hour`, `multiplier`, `next_event_time`, `active_events`
- 관리자
  - `PATCH /admin/api/events/config` (event_config 수정)
  - `POST /admin/api/events/toggle` (FORCE_ON/OFF)
  - `GET /admin/api/ops/targets` (시나리오별 대상자 리스트)

### 2.4 운영/로그/관측

- 이벤트 참여 로그 적재
  - 지급/배수 적용 시 `event_participation_log` 기록
- Ops 실행 로그 연동
  - 위기 시나리오 탐지 시 ops 로그 또는 Admin 알림
- KPI 스냅샷 저장 지점 정의
  - CCU, 티켓 소비율, 전환율, 위기 개입 성공률

### 2.5 테스트/검증

- 단위 테스트
  - `EventService.is_golden_hour()` 시간 경계
  - 세그먼트 배수 분기
- 통합 테스트
  - Dice/Roulette 보상에 배수 적용
  - Admin FORCE_ON/OFF에 따른 상태 전환
- 운영 스모크
  - `GET /api/events/status` 응답 필드
  - Scenario 대상자 리스트 생성 확인

---

## 3) 릴리즈 전략

- **기본 OFF**: `event_config.is_active=false`로 시작
- Admin 토글로 단계적 오픈
- Golden Hour 1시간만 우선 운영 → 로그/적자 확인 → 확장
