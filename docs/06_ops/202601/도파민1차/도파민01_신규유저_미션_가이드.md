# 🎁 도파민01_신규유저_미션_가이드 (New User Mission)

**문서 연결**: [도파민sot](./도파민sot.md)
**작성일**: 2026-01-14
**목적**: "고마찰(Bank)" 미션을 "저마찰(Casino)" 웰컴 기프트로 전환하여, 신규 유저가 최소한의 노력으로 시스템에 안착하게 함.

---

## 1. 목적 (Objective)
*   **Why**: 기존의 "가입해라, 3판 해라" 식의 숙제형 미션은 유저에게 스트레스를 줌.
*   **Goal**: 가입 즉시 "와, 주인이 미쳤어요!" 수준의 혜택을 퍼주어, 유저가 **"돈 따는 재미"를 5분 안에 경험**하게 만드는 것.

## 2. 유저 시나리오 (User Flow)
*   **Scenario**:
    1.  앱 실행 및 로그인 완료.
    2.  메인 로비 진입 시 **[웰컴 선물 도착]** 모달 즉시 팝업.
    3.  버튼 클릭 시 **[금고 잔액(vault_locked_balance) 2,000P + 룰렛 티켓(TICKET_ROULETTE) 5장]** 즉시 지급 (폭죽 이펙트).
    4.  "이 돈으로 당장 룰렛 돌리러 가기" 버튼 클릭 -> 게임방 이동.
*   **Core Vibe**: "공짜로 받았다!" (Reciprocity) -> "이걸로 대박 터뜨려보자!" (Opportunity).

*   **정책(Policy B)**: 전 유저에게 노출하되, **보상 수령 후에는 모달이 더 이상 뜨지 않도록** 진행도(클레임 여부)로 제어.


## 3. 기존 시스템 분석 (Legacy Analysis)
*   **[활용] 재활용 요소**:
    *   `Mission` 테이블 구조 (하단 DB Schema 참조).
    *   `MissionService.claim_reward` 로직.
*   **[주의] 충돌/변경 지점**:
    *   기존 `NEW_USER` 탭: **UX에서는 숨김 처리**(운영/디버그 목적의 데이터/로직은 유지 가능).
    *   기존 보상 `CASH_UNLOCK`:
        *   본 프로젝트 경제 SoT는 **`user.vault_locked_balance`** 이므로, 신규 웰컴 지급은 **`CASH` 신설 없이** `CASH_UNLOCK`을 사용해 **금고 잔액으로 적립**한다.
        *   (참고) 서버 내부에서 `CASH_UNLOCK`은 `POINT`로 매핑되며, 최종적으로 `vault_locked_balance`로 반영되는 구조.

### 3.1. 최종 설계 요약 (결정사항)
- 기존의 “4개 미션 완료형(그리드)” 신규유저 미션은 **폐기(사용자 UX에서 제거)**한다.
- 신규 웰컴은 **단일 모달 1클릭 수령**으로 변경한다.
- 지급은 **2개로 분리**하여 서버에서 처리한다:
  - 금고 잔액: `vault_locked_balance` (+2,000P)
    - 티켓: `TICKET_ROULETTE` (+5)
- 기존 NEW_USER 미션/탭은 **운영/디버그용으로는 유지**하되, 사용자 화면에서는 숨김 처리한다.

## 5. 기술 구현 가이드 (Technical Scope)
*   **DB Schema**:
    *   **웰컴 전용 미션 2개 추가/교체(NEW_USER 카테고리)**
        *   미션 A (금고 2,000P)
            *   `category=NEW_USER`
            *   `logic_key=NEW_USER_WELCOME_CASH`
            *   `reward_type=CASH_UNLOCK`, `reward_amount=2000`
            *   `target_value=1`, `auto_claim=true`, `is_active=true`
        *   미션 B (룰렛 티켓 5장)
            *   `category=NEW_USER`
            *   `logic_key=NEW_USER_WELCOME_TICKET`
            *   `reward_type=TICKET_ROULETTE`, `reward_amount=5`
            *   `target_value=1`, `auto_claim=true`, `is_active=true`
    *   기존 “신규유저 그리드형” 미션은 **사용자 UX 기준 폐기**
        *   권장: `is_active=false` 처리(운영/디버그에서 필요 시 재활성화 가능)
        *   삭제(DROP)는 운영 리스크가 있어 비권장
*   **Backend Logic**:
    *   **클레임 API 신설(1클릭 지급)**
        *   예: `POST /api/new-user/claim-welcome`
        *   버튼 1번 클릭으로 아래 2개를 모두 처리:
            *   `NEW_USER_WELCOME_CASH` 진행도 +1 → `auto_claim`에 의해 금고 +2,000P 지급
            *   `NEW_USER_WELCOME_TICKET` 진행도 +1 → `auto_claim`에 의해 룰렛 티켓 +5 지급
        *   멱등성(idempotency): 이미 지급(클레임)된 경우에도 **성공 응답**으로 재시도 안전하게 처리
    *   트리거 정책(Policy B): 신규유저 여부로 게이팅하지 않고, **“지급 완료 여부”로만** 모달 노출을 제어
*   **Frontend Logic**:
    *   `NewUserWelcomeModal.tsx`: 복잡한 미션 리스트 제거 → **단일 CTA(정착 지원금 받기)** UI로 교체
        *   성공 시: 금고/인벤토리 invalidate 후 “게임방 이동” 버튼 제공
    *   `HomePage`: 홈 진입 시 모달 노출 → 1클릭 지급 → 모달 닫힘(또는 자동 숨김)
    *   기존 `NEW_USER` 탭: **숨김 처리(운영/디버그 목적의 페이지/로직은 유지 가능)**

## 6. 운영 및 리스크 관리 (Ops & Risk)
*   **Admin Tool**:
    *   지급 금액/티켓 종류/개수는 어드민 **미션 관리**(`/admin/missions`)에서 `Mission` 정의를 수정하여 운영 변경.
        *   대상: `logic_key=NEW_USER_WELCOME_CASH`, `logic_key=NEW_USER_WELCOME_TICKET` (category=`NEW_USER`)
        *   참고: 이미 클레임된 유저는 영향 없음(진행도 `is_claimed` 기준).
*   **Risk Point**:
    *   **다계정작(Bonus Abusing)**: 동일 IP/기기에서 반복 가입하여 머니만 챙기는 케이스.
    *   *대응*: 지급된 머니는 **출금 전 롤링 300%** 또는 **1일 출금 제한**을 걸어, 실제 플레이 없이는 못 나가게 방어.
*   **Measurement**:
    *   로그: `mission_claim_log` (type: WELCOME).
    *   KPI: 가입 대비 웰컴 보상 수령률(Target: 95%+), 수령 후 게임 진입률(Target: 80%+).

### 7.1. 위기 대응 시나리오 (Crisis Scenarios)
단순 가입 웰컴 보상만으로는 이탈하는 유저를 잡기 위해, 다음 두 가지 위기 상황을 시스템이 감지하고 Ops Task를 생성합니다.

*   **Scenario A. "망설이는 신입" (The Hesitant)**
    *   **조건**: 가입 후 30분 경과, 게임 플레이 0회.
    *   **심리**: "먹튀인가? 조작인가?" 의심 중.
    *   **Ops Action**: "정착 지원금 5,000P" 수동 지급 명분으로 1:1 DM 발송.
    *   **System**: `ops_target_list`에 자동 등록 -> 운영자에게 알림.

*   **Scenario B. "상처받은 영혼" (The Loser)**
    *   **조건**: 가입 30분 내 잔액 100% 소진 (0원).
    *   **심리**: "아, 역시 안 되네." (빠른 포기).
    *   **Ops Action**: **[구조대 활동]** 복구용 티켓 3장 + 1,000P 지급.
    *   **System**: 중요도 'High'로 위기 감지 레이더에 표시.

## 9. 구현/검증 로그 (2026-01-14)

> 본 섹션은 **"스펙"(SoT)과 "실제 구현"의 정합성**을 유지하기 위한 작업 로그입니다.

### 9.1. 최종 사용자 플로우(현재 구현 기준)
1. 앱 로그인 후 홈(로비) 진입 → 웰컴 모달 노출(Policy B: 전 유저 노출)
2. 모달이 `/api/new-user/status` 조회
     - `NEW_USER_WELCOME_CASH` + `NEW_USER_WELCOME_TICKET`가 **둘 다 claimed**면 모달은 렌더되지 않음(자동 숨김)
3. 유저가 버튼 1회 클릭 → `/api/new-user/claim-welcome`
     - 금고 2,000P + 티켓 5장(룰렛) 지급
     - 이미 지급된 경우에도 성공 응답(멱등성)
4. 성공 연출(Lottie) 표시 + "게임방 이동" 버튼 제공

### 9.2. 프론트(모달/정책) 반영 내역
- 파일: `src/components/modal/NewUserWelcomeModal.tsx`
    - 헤더 이미지: `/assets/welcome/welcome2_header.png` (깨지면 `header_2026_newyear.png`로 fallback)
    - 티켓 이미지(번들): `/assets/asset_ticket_bundle.png` (깨지면 `asset_ticket_trial.png`로 fallback)
    - 티켓 표기: **룰렛 티켓** / reward_type 표시를 서버 응답값 우선(`ticketMission.reward_type`)
    - Policy B 숨김: status에서 두 미션이 claimed면 모달 `return null`로 미노출

- 파일: `src/pages/HomePage.tsx`
    - 홈에서 웰컴 모달을 렌더(`showModal && <NewUserWelcomeModal />`)

- 파일: `src/hooks/useNewUserWelcome.ts`
    - Policy B 트리거(전 유저 노출): 홈 진입 후 일정 딜레이로 모달 열기

### 9.4. 백엔드/DB(보상 타입) 정합화
- 룰렛 티켓 지급을 위해 reward_type은 `TICKET_ROULETTE` 사용
    - `TICKET_ROULETTE`는 서버에서 `GameTokenType.ROULETTE_COIN`으로 매핑되어 지갑에 적립됨

- 데이터 수정용 Alembic 추가(기존 마이그레이션 파일 수정 금지 원칙 준수)
    - `alembic/versions/20260114_0002_update_new_user_welcome_ticket_to_roulette.py`
    - 목적: `NEW_USER_WELCOME_TICKET`의 `reward_type`을 `TICKET_LOTTERY` → `TICKET_ROULETTE`로 업데이트
