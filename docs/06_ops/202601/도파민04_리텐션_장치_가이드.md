# 📄 도파민04_리텐션_장치_가이드 (Retention Mechanics)

**문서 연결**: [도파민sot](./도파민sot.md)
**작성일**: 2026-01-14
**목적**: 숙제처럼 느껴지는 미션과 스트릭을 **"매일 까보는 선물상자"**처럼 느끼게 하여, 자발적인 접속을 유도함.

---

## 1. 목적 (Objective)
*   **Why**: "출석체크 하세요", "좋아요 누르세요"는 노동임. 노동은 돈을 줘야 하지만, 놀이는 돈을 내고 함.
*   **Goal**: 유저가 **"내일은 뭘 줄까?"** 궁금해서 접속하게 만드는 심리적 훅(Hook) 설계.

## 2. 유저 시나리오 (User Flow)
*   **Scenario (Daily Mission)**:
    1.  접속 시 "오늘의 미션: 룰렛 잭팟 도전" 카드 노출.
    2.  성공 시 **[골드 키]** 획득.
    3.   보관함에서 **[골드 키]**로 **[랜덤 박스]** 오픈 -> 다이아/티켓/꽝 중 하나 획득.
*   **Scenario (Bailout)**:
    1.  티켓 0장 -> 게임 불가.
    2.  이탈하려는 순간 "잠깐! 구제 지원금 받으세요" 팝업.
    3.  광고 시청 or 미니게임 1판 -> 티켓 1장 부활 -> 게임 복귀.
*   **Core Vibe**: "아슬아슬했는데 살았다!" (Relief) -> "까보는 맛이 있네." (Curiosity).

## 3. 기존 시스템 분석 (Legacy Analysis)
*   **[활용] 재활용 요소**:
    *   `DailyMission` 로직.
    *   `Streak` 카운팅 로직.
*   **[주의] 충돌/변경 지점**:
    *   미션 UI: 리스트형 -> 카드형(원픽 강조)으로 전면 개편 필요.
    *   스트릭 보상: `Vault Multiplier` (보이지 않는 혜택) -> `Item` (보이는 재화)로 변경.

## 4. UI/UX 및 연출 (Visuals & Copy)
> **전제(구현 현황 반영)**
> - 도파민01/02는 구현 완료(웰컴 1클릭, VIP 골드 테마/모달 연출).
> - 도파민03의 Buy-in(금고→티켓 구매)은 계획 단계.
> - “티켓 0”은 **게임 티켓 전체 합** 기준으로 정의한다(기본 티켓+체험 티켓, 키는 별도).

### 4.1. D0 웰컴 → D1 리텐션 연결
*   **목표**: 웰컴 선물(도파민01) 수령 직후 “내일 다시 올 이유”를 즉시 심어준다.
*   **UI 구성**:
    *   웰컴 모달 성공 이후(또는 닫힘 직후), 홈 상단에 **Today 카드(원픽 미션 카드)** 노출.
    *   카드의 문장/CTA는 “숙제”가 아니라 **한 판 더**를 유도하는 문장으로 통일.
*   **Copywriting 예시**:
    *   Title: "오늘의 한 판, 잭팟 찬스"
    *   Subtitle: "티켓만 있으면 바로 도전 가능합니다"
    *   CTA: "지금 한 판 더"

### 4.2. Ticket-Zero 순간의 2단계 처리: ‘금고 유도’ → ‘구제(Trial)’
*   **정의(게임 티켓 전체)**:
    *   “플레이 가능 티켓” = 아래 토큰들의 합
        *   기본 티켓: `ROULETTE_COIN`, `DICE_TOKEN`, `LOTTERY_TICKET`
        *   구제 티켓: `TRIAL_TOKEN`
    *   프리미엄 키: `GOLD_KEY`, `DIAMOND_KEY`는 “입장권”이지만 **구제 지급 대상에서는 제외**
*   **1단계(우선): 금고 잔액이 있으면 ‘구제’가 아니라 ‘재진입’으로**
    *   “티켓 0 + 금고 잔액>0”이면 Bailout 모달보다 **금고 모달/CTA**를 먼저 띄워 “보관금으로 티켓 확보”로 연결.
    *   카피: "티켓이 0장입니다. 보관금으로 바로 한 판 더 가능해요"
    *   CTA: "티켓 채우러 가기"
    *   **Buy-in(도파민03) 반영**: Buy-in 구현 후 이 CTA가 “금고→티켓 구매”로 직접 이어지도록 설계.
*   **2단계(예외): 금고도 0이면 ‘구제’로 이탈 방지**
    *   노출 조건(권장): 플레이 가능 티켓 합이 0이고, 금고 잔액도 0인 경우.
    *   카피: "심폐소생술 들어갑니다! ⚡" / "체험 티켓 3장 지급"
    *   CTA: "체험 티켓 받기"
    *   연출: 긴급 구조대(응급키트) 느낌의 모달 + 토큰이 “부활”하는 애니메이션.

### 4.3. Streak UX: ‘달력’이 아니라 ‘보물상자 트랙’
*   **정책 제약**: 스트릭 보상은 **수동 Claim** 유지(버튼은 `claimable_day` 기반).
*   **UI 구성**:
    *   7칸 트랙 위를 걷는 캐릭터/토큰(보상 박스)로 시각화.
    *   `claimable_day`가 존재하면 해당 박스가 "열 수 있음" 상태로 펄스.
    *   Claim 후에는 “획득한 보상(티켓/다이아)”를 즉시 보여주고 지갑/인벤토리 숫자 애니메이션.
*   **Copywriting 예시**:
    *   "오늘 보물상자 열 수 있어요"
    *   "3일 연속 달성! 티켓 1장씩 지급"

### 4.4. VIP/Almost-VIP 연출(도파민02와 결합)
*   **VIP**: 세그먼트가 `VIP`인 유저는 헤더/프로필 골드 테마 유지 + “VIP 라운지” 카피로 ‘대우받는 느낌’을 강화.
*   **Almost VIP**: 레벨 9, 경험치 90% 같은 상태는 “한 끗” 카피로 당일 플레이를 유도.
    *   카피: "VIP까지 1레벨 남았어요" / "오늘 한 판이면 VIP 가능"

### 4.5. 사운드/이펙트
*   **Bailout**: 심장박동(긴급) → 지급 순간 ‘쨍’ 효과음.
*   **Box Open**: 아이템 튀어나오는 파티클 + 숫자 카운터 상승.
*   **주의**: 이펙트는 Ticket-Zero/Claim 같은 결정적 순간에 집중.

## 5. 기술 구현 가이드 (Technical Scope)
> 목표: “문서의 가정(user_items 등)”을 제거하고, **현재 코드베이스에 존재하는 SoT/테이블/서비스/엔드포인트**로 리텐션 장치를 구현/확장한다.

### 5.1. 데이터 SoT(현행)
*   **Vault(금고)**
    *   SoT: `user.vault_locked_balance`
    *   이벤트 로그: `vault_earn_event` (게임 적립/보너스 등)
    *   상태 API: `GET /api/vault/status`
*   **Wallet(게임 티켓/키)**
    *   SoT: `user_game_wallet` (`GameTokenType`별 balance)
    *   변동 로그: `user_game_wallet_ledger` (reason/label/meta 포함)
    *   Ticket-Zero 구제는 reason=`TRIAL_GRANT`로 추적
*   **Inventory(다이아/바우처/경품 대기 아이템)**
    *   SoT: `user_inventory_item`
    *   변동 로그: `user_inventory_ledger`

### 5.2. Ticket-Zero 대응(현행 구현 + 확장 계획)
*   **금고 기반 복귀(현행)**
    *   `GET /api/vault/status`에서 티켓 0 + 금고 잔액 조건일 때 `recommended_action=OPEN_VAULT_MODAL`을 내려주는 로직이 존재.
    *   현재 서버의 `ticket_count`는 3종 티켓(`DICE_TOKEN`, `ROULETTE_COIN`, `LOTTERY_TICKET`) 합으로 계산.
*   **구제(Trial Grant) 지급(현행)**
    *   엔드포인트: `POST /api/trial-grant`
    *   서비스: `TrialGrantService.grant_daily_if_empty()`
    *   정책: 일일/주간 cap 및 확률 정책은 환경 변수로 튜닝 가능(남용 방지)
    *   지급 기록: `user_game_wallet_ledger`에 reason=`TRIAL_GRANT`로 남음
    *   안전장치: 프리미엄 키(`GOLD_KEY`, `DIAMOND_KEY`)는 trial로 자동 지급 금지
*   **확장 계획(도파민03와 정합)**
    *   Ticket-Zero의 기본 해법을 “무료 지급”이 아니라 “금고→티켓(Buy-in)”로 두고,
      금고도 0일 때만 Trial Grant를 사용하도록 UX를 설계한다.
    *   UI/정책상 “게임 티켓 전체 합”에는 `TRIAL_TOKEN`까지 포함시키는 것을 최종 목표로 한다.

### 5.3. Streak(수동 Claim) 구현 기준(현행)
*   **미션/스트릭 조회(현행)**: `GET /api/mission` → `streak_info.claimable_day`로 “열 수 있음” 상태 표시
*   **스트릭 Claim(현행)**: `POST /api/mission/streak/claim`
*   **스트릭 룰(현행)**: `GET /api/mission/streak/rules` (UI config `streak_reward_rules` 우선, 없으면 fallback)

### 5.4. 프론트 구현 포인트(권장)
*   **Ticket-Zero 감지 우선순위**
    1) 서버 추천(`GET /api/vault/status`의 `recommended_action`) 우선
    2) 보조로 클라이언트에서 “게임 티켓 전체 합” 계산(지갑 응답 기반)
*   **모달 피로도 방지**: 동일 세션/단시간 중복 노출 방지를 위해 throttle(예: 30분) 적용
    *   (현행 제안) “티켓 0으로 떨어질 때마다” 노출하되, **KST 기준 하루 최대 3회**로 제한
    *   Trial Grant는 **자동 지급이 아니라 사용자 클릭 기반**으로만 동작
*   **Today 카드(원픽 미션)**: `GET /api/mission` 결과 중 1개만 강조해 “할 일”이 아니라 “한 판 더”로 보이게 한다

## 6. 운영 및 리스크 관리 (Ops & Risk)
*   **Admin Tool**:
    *   **Bailout 제한(현행)**: Trial Grant는 서버에서 일일/주간 cap 및 확률 정책으로 남용을 방지한다.
        *   기본값 예시: 일일 총량 cap=3 (전체 trial-grantable 토큰 합)
        *   조정 포인트: 일일 cap / 주간 cap / 2회차 이후 지급 확률
    *   **확률 조정(향후)**: 랜덤 박스(키→랜덤 보상) 도입 시 아이템 획득 확률을 UI config로 운영 조정.
*   **Risk Point**:
    *   **무한 파밍**: 구제 티켓만 계속 받아서 게임 돌리는 매크로.
    *   *대응(현행)*: Trial Grant는 ledger 기반 멱등/일일 cap이 기본이며, 클라이언트에서는 모달 throttle로 UX 남용을 줄인다.
*   **Measurement**:
    *   KPI: DAU(일일 활성 유저), 리텐션(D+1, D+7), 구제 후 게임 복귀율.
    *   로그: `user_game_wallet_ledger`에서 reason=`TRIAL_GRANT` 집계.

## 7. RTP & Ops System Integration (New)

> 본 가이드는 **[RTP-3.3] Macro Mission** 및 **[RTP-7.2] 상황별 DM**과 연동됩니다.

### 7.1. 거시적 목표 (Macro Mission) 개편
소액의 '출석체크' 미션들을 통합하여, **10,000원 이상의 큰 보상**을 주는 Macro Mission 체계로 격상합니다.

*   **주요 미션 Define (RTP-3.3.1)**:
    *   🎰 **플레이 마스터**: 게임 30회 플레이 -> **10,000 P + 골드키**
    *   💰 **금고 빌더**: 금고 잔액 10,000원 달성 -> **다이아몬드키**
    *   🔥 **불타는 주말**: 주말 20판 플레이 -> **5,000 P + 티켓 5장**

### 7.2. 리텐션 긴급 대응 (Ops Scenarios)
시스템 미션만으로 부족할 때, 운영자가 직접 개입하여 리텐션을 끌어올립니다.

*   **Scenario C. "잊혀진 존재" (The Sleeper)**
    *   **조건**: 3일(72시간) 미접속 & 금고에 돈이 조금이라도 있는 경우.
    *   **Ops Action**: "손실 공포(Loss Aversion)" 자극 DM 발송. ("오늘 안에 안 오면 15,000원 사라집니다!")

*   **Scenario H. "거의 다 온 사람" (Almost VIP)**
    *   **조건**: 레벨 9, 경험치 90% 달성자.
    *   **Ops Action**: 경험치 **부스터 아이템(XP x2)** 선물 지급. -> "조금만 더 하면 VIP입니다!"

### 7.3. Admin Ops Plan 연동
*   **Campaign**: `Daily Retention Boost`
*   **Routine Tasks**:
    *   [09:00] **Sleepers List Check**: 금고 1,000원 이상 보유 미접속자 추출 후 DM 발송.
    *   [12:30] **Ticket Refill Notification**: 점심시간 티켓 리필 공지(푸시) 발송 Task 실행.
