# 어드민 시스템 UI/UX 최적화 프로세스 가이드

이 문서는 어드민 시스템 내의 비효율적인 업무 흐름(UX Friction)을 식별하고, 분석하여 해결하는 개발팀의 표준 절차를 정리한 것입니다. 최근 진행한 **"회원 관리 내 금고 잔액 관리 통합"** 건을 실제 사례로 들어 각 단계를 설명합니다.

## 2. 상세 단계별 설명 (금고 관리 사례 연구)

### 1단계: 고통점 분석 (발견)
*   **계기**: 관리자가 현재의 금고 관리 방식이 너무 번거롭다고 피드백을 주었습니다.
*   **기존 흐름 (The "Pain")**:
    1.  `운영 대시보드` → 대상 유저 식별.
    2.  `회원 관리` → 유저 검색 → 상세 정보 확인.
    3.  **문제점**: 금고 잔액을 수정하려면 현재 페이지를 떠나야 함.
    4.  `금고 관리` 페이지 이동 → **낭비**: 아까 그 유저를 *또 다시* 검색해야 함.
    5.  `금고 제어 패널` → 잔액 수정.
*   **진단**: 잦은 **페이지 전환(Context Switching)**과 **중복 입력(Redundant Input)**으로 인한 높은 피로도.

### 2단계: 해결책 설계 (최적화)
*   **목표**: "기능(Action)"을 유저가 있는 "맥락(Context)"으로 가져온다.
*   **제안된 흐름**:
    1.  `회원 관리` → 유저 클릭(`V` 아이콘) → **그 자리에서 즉시 금고 수정**.
*   **타당성 분석**:
    *   *백엔드*: `adminVaultApi`가 이미 있는가? -> **예** (기존 금고 페이지에서 사용 중).
    *   *프론트엔드*: `VaultBalanceAdjuster` 컴포넌트가 있는가? -> **예**, 하지만 금고 페이지에 종속되어 있음.

### 3단계: 구현 (리팩토링 및 통합)
가장 중요한 엔지니어링 단계입니다.

1.  **컴포넌트 분리 (리팩토링)**:
    *   *이전*: 잔액 수정 폼이 `VaultAdminPage` 안에 하드코딩 되어 있었음.
    *   *작업*: 로직을 추출하여 재사용 가능한 형태로 만들거나, 대상 모달(`UserAssetDetailModal`)에서 직접 API를 호출하도록 수정.
    *   *핵심*: 수동 검색 단계 없이 `userId`를 바로 주입받아 작동하도록 변경.

2.  **맥락 통합 (Integration)**:
    *   *대상*: `UserAssetDetailModal` (통합 뷰).
    *   *작업*: 모달에 '금고 관리' 탭을 신설하고, 기존 '내역 조회'와 '강제 수정' 기능을 합침.
    *   *연결*: `UserAdminPage`의 리스트 아이템(`V` 아이콘)이 이 특정 탭을 바로 열도록 연결.

### 4단계: 검증
*   **체크**: 새로운 흐름이 식별된 병목 구간을 제거했는가?
    *   *결과*: 페이지 이동 불필요. 재검색 불필요. 클릭 한 번으로 진입 가능.
*   **안전장치**: 강제 수정과 같은 민감한 작업에 경고/확인 절차가 유지되는가? (확인 완료)

## 3. 향후 요청 시 팁

비슷한 UI/UX 개선이 필요하실 때, 다음 형식으로 요청주시면 더욱 빠르고 정확하게 처리 가능합니다:

1.  **현재 위치**: "지금 어디서 작업 중인가요?" (예: 회원 관리 리스트)
2.  **목표**: "무엇을 하고 싶은가요?" (예: 금고 잔액 수정)
3.  **현재의 불편함**: "무엇이 짜증나나요?" (예: "다른 페이지로 가서 또 검색해야 해요.")
4.  **원하는 단축경로**: "어떻게 바뀌면 좋을까요?" (예: "여기서 버튼 하나로 바로 뜨게 해주세요.")

이 프로세스를 통해 단순한 땜질식 처방이 아닌, 시스템 전체의 일관성을 유지하면서 효율을 높이는 개선이 가능합니다.
