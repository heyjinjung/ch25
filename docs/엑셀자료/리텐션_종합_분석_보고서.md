## �🔍 1. 현황 진단: 시스템 vs 실전 데이터

| 구분 | 이론 (운영 플랜) | 실전 (데이터 분석 결과) | 격차 및 기회 (Gap & Opportunity) |
| :--- | :--- | :--- | :--- |
| **웰컴 미션** | 4단계(Day 2까지) 정착 유도 | Day 2 이후 급격한 이탈 발생 | Day 1에서 Day 2로 넘어가는 **'심리적 예약'** 부족 |
| **스트릭** | 3/7일 단순 아이템 보상 | 고레벨 구간 진입 전 지루함 강화 | 3일 달성 시 **'레벨 점프(Level Jump)'** 등 속도감 필요 |
| **골든 아워** | 21:30~22:30 피크 타임 관리 | VIP와 어뷰저가 섞인 보상 구조 | VIP에게 더 높은 배수 제공하는 **'세그먼트 차등'** 필요 |
| **운영 루틴** | 매일 아침 단순 넛지(알람) 발송 | 금고 잔액이 있음에도 방치하는 유저 다수 | **'금고 잔액 기반 개인화 리콜'**로 명분 강화 |

## 💡 2. 통합 리텐션 믹스(Mix) 전략

### **① [Welcome + Reservation] : 확정형 Day 2 유입**
*   **현황**: 웰컴 미션 4단계(2일차 출석) 도달률이 핵심 지표임.
*   **강화**: Day 1 미션 완료 시 **"내일의 골든 티켓 예약"** 액션을 필수로 유도. 유저가 예약 버튼을 누르는 순간 '출석'은 '약속'으로 변함.
*   **관련 코드**: [vault_reservation](#4-day-2-보상-예약-시스템)

### **② [Streak + Level Jump] : 핵심 유저로의 고속 견인**
*   **현황**: 엑셀 데이터상 '잠재 활성군'은 3~5레벨 구간에서 정체됨.
*   **강화**: 스트릭 3일 달성 시 보상을 티켓뿐만 아니라 **'시즌 패스 +3레벨 스킵'**으로 제공. 지루한 저레벨 구간을 건너뛰게 하여 VIP 혜택(Level 10+)이 보이는 구간으로 강제 진입시킴.
*   **관련 코드**: [level_jump_reward](#2-level-jump-보상-시스템-신설)

### **③ [Admin Nudge + Vault Personalization] : 복귀 명분 극대화**
*   **현황**: 어드민에서 10명 이상 이탈 시 단순 넛지 발송 중.
*   **강화**: 넛지 메시지에 유저의 **실제 금고 잔액({vault_balance}원)**을 삽입. "잊고 계신 성민이님의 5,400원이 소멸될 수 있습니다"와 같은 개인화된 경고로 손실 회피 심리 자극.
*   **관련 코드**: [personalized_nudge](#3-개인화-넛지nudge-메시징-워커)

## 🛡️ 3. 운영 리스크 방어 (Efficiency)

현행 운영 플랜에서 간과하기 쉬운 **어뷰징 비용**을 실전 분석 기반으로 방어합니다.
*   **출금 허들 도입**: 웰컴 미션으로 퍼주는 10,000원이 그대로 출금되지 않도록, **'누적 충전 1만원 이상'** 혹은 **'50판 플레이'** 조건을 출금 필수 게이트로 설정.
*   **다이나믹 부스트**: 골든 아워 2.0x 배수를 적용할 때, `어뷰징` 태그 유저는 즉시 0.5x로 하향 처리하여 마케팅 예산 누수 방지.

## ⚙️ 4. 구체적 기술 구현 계획 (Implementation Plan)

### **1) Vault Multiplier 엔진 고도화**
- **목표**: 유저의 세그먼트(VIP vs 어뷰저) 및 레벨에 따라 실시간으로 금고 적립 배수를 조정.
- **수정 대상**: `app/services/vault_service.py`
- **로직**:
  ```python
  def get_custom_multiplier(user: User):
      multiplier = 1.0
      if user.level >= 10: multiplier *= 1.5  # VIP 버프
      if "어뷰징" in user.tags: multiplier *= 0.5 # 패널티
      return multiplier
  ```

### **2) Level Jump 보상 시스템 (Detailed Spec)**
미션 보상으로 단순 XP가 아닌 '즉시 레벨업' 기능을 구현하여, 유저를 고가치 보상이 포진된 상위 구간으로 빠르게 견인합니다.

#### **A. Backend: Logic (RewardService)**
*   **수정 대상**: `app/models/mission.py` (Enum), `app/services/reward_service.py`
*   **구현 로직**: 
    - `MissionRewardType`에 `LEVEL_UP` 추가.
    - `RewardService.deliver()` 함수 내에 `reward_type == "LEVEL_UP"` 조건 추가.
    - 처리 로직:
      ```python
      def process_level_jump(user, amount):
          old_level = user.level
          user.level += amount
          # 기존 XP 유지 혹은 다음 레벨 목표치에 맞춰 보정 로직 추가
          sync_level_progress(user) 
      ```

#### **B. API & Schema (Missions)**
*   **Schema**: `app/schemas/mission.py` (또는 기존 Claim 결과 스키마)
    ```python
    class MissionClaimResult(BaseModel):
        success: bool
        reward_type: str
        level_jump: Optional[dict] = { "old": 5, "new": 8 }
    ```
*   **Endpoint**: `POST /api/missions/{mission_id}/claim`
    *   보상 수령 시 응답 데이터에 `level_jump` 정보를 포함하여 프론트엔드에서 연출을 트리거할 수 있도록 함.

#### **C. Frontend (UX Animation)**
*   **컴포넌트**: `src/components/effects/LevelUpSplash.tsx`
*   **연출 가이드**:
    *   미션 수령 버튼 클릭 -> 서버 응답에 `level_jump` 포함 확인.
    *   화면 중앙에 "LEVEL UP!" 텍스트와 함께 `+3` 혹은 `SKIPPED` 애니메이션 노출.
    *   프로필 영역의 레벨 숫자가 빠르게 카운트업(Odometer 효과)되며 게이지가 차오르는 연출.

#### **D. Operation (Seeding)**
*   **데이터**: 스트릭 3일 미션의 `reward_type`을 `LEVEL_UP`으로, `reward_amount`를 `3`으로 설정하여 DB에 적재.

### **3) 개인화 넛지(Nudge) 메시징 워커 (Detailed Spec)**
유저의 실제 자산 상태를 메시지에 담아 '손실 회피' 심리를 자극하고 복귀 명분을 제공하는 자동화 시스템입니다.

#### **A. Backend: Messaging Worker**
*   **수정 대상**: `app/services/mission_service.py` (또는 전용 `NudgeService`), `app/core/telegram.py`
*   **구현 로직**: 
    - 템플릿 엔진: `{nickname}`, `{balance}`, `{streak}` 등의 변수를 치환하는 간단한 파서(Parser) 구현.
    - 배치 처리: `last_login_at`이 24시간~48시간 사이인 유저를 추출하여 텔레그램 `send_message` API 호출.
    ```python
    def send_personalized_nudge(user: User):
        template = "🔥 {nickname}님! 금고의 {balance}원이 기다리고 있어요!"
        message = template.format(
            nickname=user.nickname, 
            balance=f"{user.vault_locked_balance:,}"
        )
        telegram_bot.send_message(user.telegram_id, message)
    ```

#### **B. API & Schema (Admin System)**
*   **Schema**: `app/schemas/admin_crm.py`
    ```python
    class BulkNudgeRequest(BaseModel):
        target_segment: str # "RISK_GROUP", "VALUED_VIP"
        template_id: str
        is_dry_run: bool = True # 실제 발송 전 대상 수 확인용
    ```
*   **Endpoint**: `POST /api/admin/crm/nudge`
    *   어드민에서 버튼 클릭 시 특정 세그먼트 유저들에게 개인화 메시지를 일괄 발송하는 트리거.

#### **C. Frontend (Admin CRM Dashboard)**
*   **컴포넌트**: `src/admin/components/CRM/NudgeConsole.tsx`
*   **기능 구성**:
    - **프리뷰(Preview)**: 특정 유저 ID를 입력하면 그 유저의 데이터가 바인딩된 실제 메시지 예시를 미리 확인.
    - **발송 스탯**: 총 대상자 수, 성공 수, 실패 수 등을 실시간 프로그레스 바로 노출.
    - **타겟팅 필터**: 금고 잔액 5,000원 이상, 스트릭 3일 이상 등 세부 필터링 UI.

#### **D. Data Integration**
*   **트래킹**: 넛지 발송 후 `UserEventLog`에 `crm.nudge_sent` 기록하여, 이후 유저의 실제 접속 여부(Conversion) 측정.

### **4) Day 2 보상 예약 시스템 (Detailed Spec)**
유저가 첫날 활동을 마치기 전 '내일의 보상'을 직접 예약하게 함으로써 재방문율을 높이는 시스템입니다.

#### **A. Backend: Data Model (User)**
*   **Column 추가**: `app/models/user.py`
    *   `has_reserved_next_day_reward`: `Boolean` (예약 여부)
    *   `reward_reserved_at`: `DateTime` (예약 시점 - 다음 날 검증용)
    *   `reserved_reward_type`: `String(50)` (예약된 보상의 ID/타입)

#### **B. API & Schema (FastAPI)**
*   **Schema**: `app/schemas/vault.py`
    ```python
    class ReservationIn(BaseModel):
        reward_type: str = Field(..., example="GOLD_KEY_PACKAGE")
    ```
*   **Endpoint**: `POST /api/vault/reserve`
    *   **Logic**: 유저의 `has_reserved`를 `True`로 전환하고 `reserved_at`에 현재 서버 시간 기록. 1일 1회만 예약 가능하도록 벨리데이션 포함.

#### **C. Logic (VaultService)**
*   **지급 시점**: 유저 첫 로그인 시 호출되는 `login_streak` 혹은 `sync_play_streak` 로직 내에서 자동 검사.
*   **검증 로직**: `now_kst.date() > reward_reserved_at_kst.date()` 일 때만 유효한 예약으로 간주하여 보상 지급 처리.

#### **D. Frontend (React/TypeScript)**
*   **예약 모달**: 웰컴 미션 3단계 완료 시 `ReservationModal.tsx` 팝업 노출.
*   **상태 표시**: 헤더 혹은 금고 대시보드에서 '내일 보상 예약됨' 아이콘 노출.
*   **API 연동**: `useApi` 훅을 사용하여 버튼 클릭 시 `/api/vault/reserve` 호출.
