# 리텐션 마케팅 데이터 전략: "골든 레코드(Golden Record)"

단순한 "충전 기반 세그먼트"에서 벗어나 "행동 기반 리텐션"으로 진화하기 위해서는 시스템 로그를 풍부하게 만들어야 합니다. 현재 우리는 *트랜잭션*(입금/금고)과 *이벤트*(플레이)는 기록하고 있지만, 유저의 *맥락(Context)*과 *감정(Sentiment)* 신호는 놓치고 있습니다.

마케팅 전문가 관점에서, 진정한 "유저 골든 레코드"를 구축하기 위해 다음 4가지 레이어의 데이터 수집을 제안합니다.

## 1. "감정(Sentiment)" 레이어 (이탈 방지 핵심)
**목표:** 유저가 좌절하거나 "틸팅(Tilting - 멘탈 붕괴)" 오는 순간을 포착하여 떠나기 전에 잡는다.
*   **게임 결과 로그 (Game Outcome Logs)**:
    *   현재: `ROULETTE_PLAY` (단순 횟수)
    *   **필요**: `ROULETTE_RESULT` -> `{ bet_amount: 1000, win_amount: 0, balance_after: 5000 }`
    *   **이유**: "연패 스트릭(Loss Streaks)" 계산 (예: 10연패 중).
    *   **액션**: 즉시 "불운 위로금" 또는 "구제 금융" 알림 발송.
*   **"올인(All-In)" 이벤트**:
    *   **필요**: `bet_amount == available_balance` 인 순간을 별도로 로깅.
    *   **이유**: 가장 위험한 순간입니다. 여기서 패배하면 이탈 확률이 극대화됩니다.

## 2. "참여(Engagement)" 레이어 (타이밍이 생명)
**목표:** 유저가 실제로 폰을 보고 있을 때 메시지를 보낸다.
*   **세션 심박수 (Session Heartbeats)**:
    *   **필요**: `LOGIN_TIMESTAMP` 및 `LAST_ACTION_TIMESTAMP` (또는 주기적 생존신호).
    *   **이유**: "프라임 타임" 파악. 유저 A는 새벽 2시에만 게임하나요? 아침 9시에 SMS 보내지 마세요.
*   **아이쇼핑 (Window Shopping - 의도 파악)**:
    *   **필요**: 구매 없이 `Shop` 또는 `Exchange` 페이지를 조회한 로그.
    *   **이유**: 사고 싶은데 망설이는 중입니다.
    *   **액션**: "상점 아이템 5% 깜짝 할인" 팝업 노출.

## 3. "지갑(Wallet)" 레이어 (구매력 분석)
**목표:** 유저 그릇에 맞는 오퍼를 제공한다.
*   **지갑 속도 (Wallet Velocity)**:
    *   **필요**: 소진 속도(Burn rate). `분당 소모 토큰`.
    *   **이유**: "그라인더(소액으로 오래 노는 유저)"와 "하이롤러(순식간에 태우는 유저)" 구분.
    *   **액션**: 그라인더에겐 "시간제 버프", 하이롤러에겐 "즉시 지급 캐시" 제안.
*   **재화 선호도 (Currency Preference)**:
    *   **필요**: `Gold` vs `Diamond` 사용 비율.
    *   **이유**: 다이아만 쓰는 유저에게 골드 보상을 주지 마세요.

## 4. "반응(Reaction)" 레이어 (캠페인 건강도)
**목표:** 죽은 캠페인에 예산을 낭비하지 않는다.
*   **알림 클릭률 (Notification Click-throughs)**:
    *   **필요**: 텔레그램/SMS의 딥링크를 타고 들어온 시점 로깅.
    *   **이유**: "마케팅 수용성 점수(Marketing Receptiveness Score)" 산출.
*   **보상 소진율 (Bonus Utilization Rate)**:
    *   **필요**: "보상 수령" 후 "실제 사용"까지 걸린 시간.
    *   **이유**: 보상을 쟁겨두기만 한다면 흥미가 떨어진 상태입니다. 즉시 쓴다면 콘텐츠에 굶주린 상태입니다.

## 구현 우선순위 (MVP)
1.  **`ActivityRecord` 강화**: `metadata` JSON 필드를 추가하여 `win_amount`, `bet_amount`, `result` 저장.
2.  **세션 트래킹**: 간단한 `user_login` 로그 테이블 구축.
3.  **연패 계산기**: `ActivityRecord`를 스캔하여 연속 0원 당첨(패배)을 감지하는 백그라운드 잡.

이 데이터가 모이면 우리는 이렇게 변할 수 있습니다:
> "유저가 7일간 충전을 안 했네요." (후행 지표)
에서
> "유저가 방금 5연패를 당하고 상점 페이지에서 망설이고 있네요." (선행 지표)
로 진화합니다.
